# ILP 기반 직무역량 과목 추천 시스템 — 설계 문서

> 본 문서는 "성적표 기반으로 학생 역량을 추정하고, 목표 직무의 부족 역량을 메우는 과목들을 졸업요건을 고려한 시간표 형태로 추천"하는 시스템의 최적화 엔진 설계를 정리한다. ILP(정수선형계획법)의 구성요소 순서로 기술하며, 설계 과정에서 검토·기각·채택한 선택지와 그 근거를 함께 담아 구현에 바로 활용할 수 있도록 한다.

---

## 0. 문제 정의와 접근 방법론

### 0.1 목표

학생의 성적표(기수강 과목 + 성적)를 입력받아, 학생이 목표하는 직무에 대해 부족한 역량을 메우는 26-2학기 과목 조합을 **시간표 단위로** 추천한다. 이때 시간 충돌·학점 상한·졸업요건 등 실제 수강신청에서 고려하는 제약을 만족해야 한다.

### 0.2 방법론 선택 — 왜 ILP인가

문제를 세 질문으로 분해하면: (1) 무엇이 좋은 과목인가(점수화), (2) 어떤 조합이 타당한가(제약 만족), (3) 타당한 공간에서 최선을 어떻게 찾는가(탐색). 이 셋을 하나로 푸는 패러다임으로 수리최적화(ILP), 추천시스템, 메타휴리스틱, 제약프로그래밍(CP) 등을 검토했다.

검토 결과 ILP를 채택한 근거는, 이 문제의 모든 구성요소가 ILP의 형태와 정확히 일치하기 때문이다.

- **결정의 본질이 0-1 선택**: "각 분반을 시간표에 넣을지 말지"는 쪼갤 수 없는 이진 선택이다. → 이진 정수변수.
- **모든 제약이 선형 부등식**: 시간충돌·학점상한·한과목한분반·기수강금지가 전부 결정변수의 1차식으로 표현된다. 비선형이 없다.
- **목적이 선형**: "직무 갭 보완 점수 합 최대화"가 선형 목적함수다.

또한 ILP는 두 가지 보장을 제공한다. **(1) 타당성 보장** — hard 제약을 위반하는 해는 후보에서 원천 배제되어, 시간충돌·학점초과가 구조적으로 0%다. **(2) 최적성 보장** — "제약을 만족하는 모든 시간표 중 최적"임이 증명된 해를 반환한다. 이는 LLM 프롬프팅(제약 위반·재현성 문제)이나 메타휴리스틱(최적성 미보장)과의 결정적 차별점이다.

규모(26-2 후보 약 235개 과목, 762개 분반)가 작아 ILP 솔버가 최적해를 빠르게 찾을 수 있어, 휴리스틱으로 최적성을 포기할 이유가 없다. CP도 가능하나, 시간충돌이 이산 슬롯 부등식으로 충분히 표현되어 CP 전역제약의 이점이 크지 않다.

**솔버**: PuLP + CBC(COIN-OR) 채택. 무료·오픈소스이며 이 규모(이진변수 ~762개)는 밀리초~초 단위로 최적해를 보장한다. lexicographic 2단계(1순위 풀이→V* 고정→2순위 재풀이)가 간단히 구현된다. OR-Tools(CP-SAT)는 위 이유로, Gurobi/CPLEX는 라이선스 비용 때문에 이 규모에 불필요.

## 1. 결정변수 (Decision Variables)

```
x_c ∈ {0, 1}    분반 c를 시간표에 포함하면 1, 아니면 0
```

**후보집합 C** = 26-2 개설분반 ∩ (학생 dept 관련 졸업요건 영역). 구체적으로 `course_section ⋈ course`에서 `source_term = <적재 학기>` AND `dept_id ∈ {IDE, BIZ, COMMON}` AND `area ≠ 일반선택`으로 필터한 약 **235개 과목 / 762개 분반**.

- **카탈로그 확장 반영**: catalog가 192→3,304로 확장되면서 DB의 `course`는 이제 전체 universe(성적표 역량매칭용)다. 따라서 후보 한정은 더 이상 "DB에 반영"이 아니라 **ILP 쿼리에서 명시적으로 필터**해야 한다.
- **일반선택 제외 결정**: merge_catalog가 타 학과 전공(컴공 자료구조 등)을 `area=일반선택`으로 환산해 두어, 일반선택을 포함하면 타과 과목이 후보로 새어든다. "직무 역량 갭 보완 + 우리 학과 추천"이라는 정체성에 맞춰 일반선택(COMMON, 46과목/162분반)은 후보에서 제외한다. IDE/BIZ 전공·MSC·교양·전공기초영어만 후보.
- 후보 234과목 = 커레이트 117 + 크롤 117(전부 공통교양/교양필수/MSC). 전공과목은 모두 커레이트분에서 오므로 선수정보가 완전하다(3.4 참조).

## 2. 파라미터 (Parameters)

목적함수·제약에 들어가는 상수. 솔버 실행 전에 성적표와 DB로부터 계산되어야 한다.

### 2.1 DB에서 직접 오는 값

| 기호 | 의미 | 출처 |
|------|------|------|
| credit_c | 과목 c의 학점 | course |
| ρ_k | 목표 직무가 역량 k를 요구(중시)하는 수준, 0~1 (10개 역량, 합≠1) | job_competency |
| w_{c,k} | 과목 c가 역량 k에 기여하는 비중. 매핑 산출은 과목별 **합 = relevance r_c ≤ 1** (데이터 무관 과목은 0에 가까움, 매핑 05). 추천에는 **과목별 상위 K=3 역량만** 쓴다(2.3, #31) | course_competency |
| min_credits_g | 졸업요건 영역 g의 최소학점 | graduation_requirement |
| 시간슬롯, area_c | 분반 시간표, 과목 영역 | course_section, course |

**역량 taxonomy (10개)**: PROG, DATA, ML, DB, VIZ, BIZ, FIN, MKT, OR, COMM

### 2.2 성적표 + DB로 계산하는 값

아래 σ → gap → Score, 그리고 need는 본 시스템의 핵심 파생 파라미터다. 계산 정의는 목적함수(4절)에서 도출 근거와 함께 기술한다.

| 기호 | 의미 |
|------|------|
| σ_k | 학생의 현재 역량 보유 수준 (10차원, 0~1) |
| gap_k | 직무 대비 학생이 약한 방향 |
| Score_c | 후보 과목 c의 직무 적합도 |
| need_g | 졸업요건 영역 g의 남은 부족 학점 |

### 2.3 튜닝 파라미터 (구조에 영향 없음, 값만 조정)

| 기호 | 의미 | 기본값 |
|------|------|--------|
| α | σ 포화곡선의 가파름 | 1.5 (grade_factor 스케일에 맞춰 튜닝) |
| grade_factor | 성적 → [0,1] 계수 | **grade / 4.5** (학칙 평점 정규화) |
| ε | 1순위 완화 여유 | 0 (필요시 도입) |
| U, L | 학점 상한/하한 | 18(사용자 18/21) / 12 |
| K | 과목 하나가 σ·Score에 기여하는 역량 수 | **3** (`params.COURSE_TOP_K`) |

**grade_factor = grade/4.5 채택 근거**: 학수번호 성적(4.5 만점)을 그대로 정규화한다. 임의의 매핑표(예: A+1.0/B0 0.7)는 "왜 그 값?"에 답이 없으나, 학칙 평점은 "학교가 정한 비율을 그대로 쓴다"가 답이 된다. `transcript.student_course.grade`가 이미 4.5 스케일이라 매핑표 없이 직접 사용. F(0)는 passed=0이라 σ에 애초에 안 들어가고, 실제 σ 기여 최저는 D0=0.22.
- **P/N → 1.0(A+ 취급)**: 통과를 만점으로 관대하게 인정. "1은 과대평가"라는 일반 우려가 있으나, 성적표당 P/N은 소수이고 대개 교양이라 10개 역량에 약하게 매핑돼 영향이 작다. ⚠️ 구현 시 `load.py`가 P/N grade를 0.0으로 저장하므로 `is_pn=1`이면 저장값 무시하고 1.0 적용.
- **미상(파싱실패) → 0.67(B0)**: P/N과 원인이 달라 분리. 신입생은 기수강 0이라 무관.
**K = 3 채택 근거 (#31)**: 매핑 벡터는 과목마다 10역량 전부에 값이 있고, 순위별 중앙값이 1위 0.157 · 2위 0.069 · 3위 0.048 · 4위 0.039 · 5위 0.033으로 4위부터 평평하다. 이 꼬리는 KoSBERT 유사도가 모든 역량에 고르게 까는 바닥이다(역량매핑_시행착오 2절, anisotropy). 매핑 검증은 argmax·top3만 봤지만 σ는 벡터 전체를 과목 수만큼 누적하므로, 과목이 쌓일수록 바닥이 모든 역량 σ를 같이 밀어 올려 직무 간 적합도 차이가 무너졌다. 산데공 경로(1학년 샘플 → 전공·MSC 지정 학년 순) 28과목에서 직무 6개 적합도 격차가 30.5 → 17.1로 줄었고, 경영 3학년 샘플은 데이터 사이언티스트 93.9 · PM 99.7로 사실상 구분이 없었다. 상위 3역량만 남기면 28과목 격차 36.9, 경영 샘플은 DS 78.9 · PM 99.7로 갈린다. 절대 문턱(w ≥ 0.10)도 격차는 비슷했으나 가중치 스케일에 묶이고 과목 1,250개가 기여 0이 되어 기각. 측정 자는 `python -m recommender.diagnose`.
- 절대 스케일은 α에 흡수되므로(σ=1−exp(−α·Σ grade·w)), grade_factor 전체를 상수배해도 α 재튜닝과 동치. 정규화로 [0,1]을 유지해 α 직관을 보존한다.

## 3. 제약조건 (Constraints)

### 3.1 설계 원칙 — hard와 soft의 구분

- **hard 제약**: 위반 시 불가능. 제약식으로 들어가며 솔버가 위반 해를 후보에서 배제(위반 0%). 단, 과도하면 infeasible(해 없음) 위험.
- **soft 제약**: 위반 가능하되 점수 손해. 목적함수의 보너스/페널티 항으로 들어감. 해를 깨뜨리지 않음.

원칙: "어기면 수강·졸업이 실제로 불가능한 것만 hard, 선호·권장은 soft."

### 3.2 Hard 제약 (확정)

| # | 제약 | 수식 | 근거 |
|---|------|------|------|
| A1 | 시간 충돌 금지 | 모든 슬롯 s: Σ_{c∈s} x_c ≤ 1 | 동시간 두 과목 수강 불가. **time_slots_int NULL(28분반: 비대면/논문/실습)은 어느 슬롯에도 안 들어가 제약에서 자동 제외**(상시 수강가능) |
| A2 | 한 과목당 분반 하나 | 모든 과목 m: Σ_{c∈분반(m)} x_c ≤ 1 | 동일 과목 중복 수강 불가. 분반(m)=course_id 공유 section들 |
| A3 | 학점 상한 | Σ_c credit_c·x_c ≤ U | 학기 최대 이수학점 (사용자 입력 18/21) |
| A3′ | 학점 하한 | Σ_c credit_c·x_c ≥ L | 행정 강제 아니나 정상 수강 가이드(기본 12) |
| B1 | 기수강 과목 금지 | x_c = 0 (기수강 c) | 재수강 포함, 성적표에 있는 과목 전부 제외(학점·성적 무관) |
| B2 | 선수과목 미충족 금지 | x_c = 0 (선수 p ∉ 기수강) | 선수과목을 안 들은 학생에게 상위과목을 추천하지 않음. 사전계산으로 처리(3.4) |
| B3 | 공강 요일 수업 금지 | x_c = 0 (c 의 슬롯 중 하나라도 공강 요일) | 학생이 비우겠다고 고른 요일(월~금, 여러 날 가능). 후보 사전필터라 식·동점 결정은 그대로. 시간 미지정 분반은 남는다. 못 채우면 조건을 풀지 않고 빈 결과(#77) |

### 3.3 Soft로 전환된 항목 (→ 목적함수로 이동)

| 항목 | 왜 hard가 아닌가 | 처리 |
|------|------------------|------|
| 졸업요건 진척 (C1) | 졸업까지 누적요건이라 한 학기에 hard 강제 시 infeasible | 2순위 목적함수 (4.3) |

(선수과목은 당초 soft 후보였으나 데이터 검증 결과 hard로 확정 — 3.4 참조.)

### 3.4 선수과목을 hard로 둔 근거 (당초 soft에서 정정)

선수과목은 hard 제약(B2)으로 처리한다. **선수를 안 들은 학생에게 상위과목을 추천하는 것은 부적절한 조언**이라는 판단이며, 데이터 검증으로 뒷받침된다.

**핵심 정정 — "데이터 한계"가 아니라 "선수 없음"이다.** 당초 "193과목 중 14과목만 선수정보 → 나머지는 데이터 누락 → hard 시 비대칭"으로 보아 soft로 두려 했으나, 실측 결과 이는 오해였다.
1. **커레이트분의 선수 필드는 권위적(complete)**: 선수 있는 14과목은 전부 본질적으로 선수가 필요한 과목(캡스톤, 의사결정(2)←(1), 데이터기반최적화, 외국어(2)←(1), 파이썬응용 등)이고, 나머지 179과목은 데이터 누락이 아니라 **진짜 선수가 없는** 입문·독립 과목이다.
2. **후보집합 안에서 선수정보가 사실상 완전**: 후보 234과목 = 커레이트 117 + 크롤 117인데, 크롤분은 전부 공통교양/교양필수/MSC(선수 거의 없음)이고 **선수를 가질 수 있는 전공과목은 모두 커레이트분(선수 필드 채워짐)에서 온다.** 따라서 "14개만 강제되는 비대칭"은 후보집합에 적용하면 거의 존재하지 않는다.

**행정 비강제와의 관계**: 홍익 IDE는 선수를 행정적으로 강제하지 않아 선수 없이 상위과목 수강이 *가능*은 하다. 그러나 추천 시스템은 "수강 가능한 것"이 아니라 "수강하면 좋은 것"을 제시해야 하므로, 준비되지 않은 과목은 추천에서 배제하는 것이 옳다. 즉 행정적 허용에도 불구하고 **추천 품질을 위해 hard로 강제**한다.

**infeasible 위험**: 후보가 234과목으로 넓어 선수 차단으로 해가 사라질 위험은 낮다.

→ 구현: 과목 c의 선수 p가 학생 기수강(passed)에 없으면 `x_c=0`(사전계산). **잔여 한계**: 스키마가 단일 course_id라 "A and B"·"A or B" 복합 선수조건은 표현 못 함(현 14건은 단일 체인이라 실질 문제 거의 없음). 8절에 명시.

### 3.5 졸업요건 영역 처리 (7개만 모델 반영)

course.area와 졸업요건 area를 대조한 결과 (영역 집합은 **dept별로 다름** — IDE 2026/BIZ 2022 각각의 graduation_requirement에서 동적 도출):

| 영역 | 처리 |
|------|------|
| 교양필수, 공통교양, MSC, 전공필수, 전공선택, 전공기초영어 (BIZ는 전공기초 등) | ✅ course.area와 1:1 매핑, 하한(min_credits)으로 need 계산 |
| 일반선택 | △ need_g는 계산되나, 후보집합 C에서 일반선택을 제외(1절)했으므로 **추천으로는 채워지지 않음**(학생이 타과 과목으로 자율 충족). GradProgress 대상 아님 |
| 특성화교양, SW데이터활용역량 | ❌ 매핑 과목 0개(타 트랙) → 모델 제외, UI에 "미고려" 명시 |
| 교양총합 cap (40) | ❌ binding 거의 없음 → MVP 제외, UI에 "교양 상한 미고려" 명시 |

- **정원(D2)**: 고려하지 않음.

## 4. 목적함수 (Objective Function)

### 4.1 정식화 방식 — 우선순위형 목표계획법 채택

**문제 성격**: 목표가 복수다 — (1) 직무적합, (2) 졸업진척, (3) 선수준수.

**검토한 세 방식**

- **가중합** (`max λ·직무 + μ·졸업`): 단순하나 가중치 λ:μ의 설정 근거가 약하다(발표에서 가장 빈번히 받은 질문). 두 점수 스케일이 다르면 가중치가 중요도와 단위보정을 동시에 떠안아 해석이 모호하다.
- **목표계획법 일반형** (`min w₁·d₁⁻ + w₂·d₂⁻`): 스케일에 강하나 정해야 할 임의값이 오히려 늘어난다(가중치 + 목표치). 가중치 임의성이 목표치 임의성으로 전이될 뿐이다.
- **우선순위형(Lexicographic) 목표계획법** ✅ **채택**: 목표를 가중치로 섞지 않고 순위를 매겨 순차 최적화한다.

**채택 근거**

1. **가중치 임의성 제거**: 정해야 할 것이 목표 간 순서뿐. "가중치를 어떻게 정했나"에 "섞지 않았다"는 근본적 답이 가능하다.
2. **우선순위가 시스템 정체성과 일치**: 본 시스템의 존재 이유가 "직무 역량 갭 보완"이므로 직무적합이 1순위인 것이 문제 정의로부터 도출된다. 졸업진척은 "직무를 채우면서 졸업도 챙긴다"는 보조 목표이므로 2순위가 자연스럽다.
3. **제약 만족은 방식과 무관하게 보장**: 정식화 방식과 무관하게 hard 제약은 항상 100% 만족된다. 우선순위형은 실행가능 영역 안에서 해를 선택할 뿐이다.

### 4.2 1순위 목적함수 — 직무적합 (CareerFit)

```
max  CareerFit(x)
→ 최적값 V* 확보
```

(선수과목은 hard 제약 B2로 처리되어 목적함수에 페널티 항이 없다. 당초 μ_pre 항은 3.4 정정으로 제거.)

#### 4.2.1 CareerFit 도출

"선택 과목들이 목표 직무의 부족 역량을 얼마나 메우는가"를 측정한다. 안→밖 순서로 도출한다.

**(1) σ_k — 학생 현재 역량 (성적 반영 지점)**

```
σ_k = 1 − exp( −α · Σ_{c ∈ 기수강} grade_factor(c) · w_{c,k} )
```

- **요소**: 기수강 과목(역량의 출처), grade_factor(성적 가중), w_{c,k}(역량 기여), Σ(누적), 포화변환.
- **성적 가중 근거**: 성적표 기반 시스템의 차별점이 "성적까지 본다"는 점이다. A+로 들은 과목과 C로 통과한 과목을 동일시하지 않는다. **grade_factor = grade/4.5**(학칙 평점 정규화, 2.3절). P/N은 1.0(통과를 관대 인정), 미상(파싱실패)은 0.67(B0 중립)로 대체. F는 passed=0이라 합산에 애초에 포함되지 않는다.
- **포화변환 근거**: w_{c,k}는 과목 내 상대비중(합 ≤ 1, relevance 반영)이라 단순 누적하면 무한정 커져 ρ(0~1)를 추월하고, gap이 전부 0이 되어 목적함수가 비어버린다. 포화함수 `1−exp(−α·)`는 (a) [0,1]로 자동 압축되어 gap 신호가 항상 살아있고, (b) clip이 아닌 점근이라 과목 수에 따른 역량 깊이를 보존하며, (c) "초기 빠른 습득 후 수확체감"이라는 학습곡선과 일치한다. min(1,·)은 깊이를 잃고, 최대치 정규화는 분모가 자의적이라 기각.
- **credit 미포함 근거**: σ는 "역량 방향 진척도"이므로 비율 누적의 포화로 충분하다. credit은 CareerFit 바깥에서 학습량으로 한 번 곱해지므로, σ 안에 또 넣으면 이중 반영이 된다.

**(2) gap_k — 직무 대비 약한 방향**

```
gap_k = max(0, ρ_k − σ_k)
```

- **방향 해석(방식 Y) 채택**: ρ_k를 "도달해야 할 절대 목표량"이 아니라 "직무가 역량 k를 중시하는 정도(방향·우선순위)"로 해석한다. gap_k는 "직무가 중시하는 방향 중 학생이 아직 상대적으로 약한 부분"이다. 이로써 (a) "각 직무마다 채워야 할 절대량이 있느냐"는 질문을 우회하고, (b) ρ의 비정규화(합≠1)가 정당해지며, (c) 같은 직무라도 학생 역량에 따라 추천이 달라지는 개인화가 유지된다.
- **max(0,·) 근거**: 직무가 중시하는 수준을 이미 넘어선 역량은 더 강조하지 않는다(0). 음수 처리 시 "이미 잘하는 역량 수강"이 처벌받는 비직관이 생기므로 0에서 절단.
- **스케일에 관한 정직한 입장**: ρ_k의 0~1(데이터 고정)과 σ_k의 0~1(α가 만든 스케일)은 **엄밀히 동일 척도가 아니다.** 따라서 gap의 절대값에 물리적 의미를 부여하지 않는다. gap은 과목을 직무적합 순으로 **줄 세우기 위한 상대 점수**이며, 필요한 것은 두 단조성(ρ↑→gap↑, σ↑→gap↓)뿐이고 이는 뺄셈으로 보존된다. 역량 간 합산(Σ_k)의 스케일 차이는 한계로 인정하되, 민감도 분석으로 추천 안정성을 확인한다.

**(3) Score_c — 과목의 직무 적합도**

```
Score_c = Σ_k gap_k · w_{c,k}
```

갭 벡터와 과목 기여 벡터의 내적. "직무가 중시하고 학생이 약한 방향(gap_k↑)을 많이 다루는(w_{c,k}↑) 과목"일수록 높다. gap=0인 역량은 자동 무시된다.

**(4) CareerFit — 시간표 전체 직무적합**

```
CareerFit(x) = Σ_c credit_c · Score_c · x_c
```

- **credit 곱 근거**: "한정된 학점 예산(≤U) 안에서 갭 보완을 최대화"하는 배낭문제(knapsack) 구조가 되어 학점상한 제약(A3)과 의미가 맞물린다. 대부분 3학점이라 실질 차이는 작으나 논리적으로 깔끔하다.

### 4.3 2순위 목적함수 — 졸업진척 (GradProgress)

```
max  GradProgress(x)
s.t. CareerFit(x) ≥ V*    (1순위 고정, ε 완화 시 (1−ε)·V*)
     + 모든 hard 제약 (A1·A2·A3·A3′·B1·B2·B3)
```

#### 4.3.1 GradProgress 도출

"선택 과목들이 졸업을 얼마나 진전시키는가"를 측정한다. CareerFit과 달리 "학점"이라는 절대 단위를 다루므로 스케일 문제가 없다.

**(1) need_g — 영역별 졸업 부족분**

```
need_g = max(0, min_credits_g − 기이수학점_g)       (7개 영역 각각)
```

기이수학점_g는 성적표를 area별로 집계해 얻는다. 단 **학생 학과 기준**으로 집계한다 —
타 학과의 전공 영역(전공필수·전공선택·전공기초·MSC) 과목은 이름이 같아도 다른 요건이라
일반선택으로 인정하고, 교양 영역은 전교 공통이라 개설 학과와 무관하게 그대로 인정한다(#40).
경영 전공필수 18학점이 산업데이터공학과 전공필수 12학점을 채워 버리던 결함을 막는다.

**(2) GradProgress**

```
GradProgress(x) = Σ_g min( need_g , Σ_{c∈영역 g} credit_c · x_c )    (need-cap)
```

- **need-cap 채택 (당초 cap 무시에서 변경)**: 영역 g의 보상을 **need_g에서 포화**시킨다. 이진 방식(`1[need>0]·credit`)은 영역이 "부족하기만 하면" 초과분도 무한정 보상해, **need가 작은 영역을 과적재**하는 문제가 있었다(실측: MSC가 2학점만 모자란데 6학점 추천, 그 4학점을 39학점 모자란 전공선택에 쓰는 게 나은데도). min 포화는 "필요한 만큼만" 보상해 남은 양이 큰 영역으로 자연히 분배된다.
- **선형화**: min은 비선형이라 보조변수 f_g로 표현 — `f_g ≤ need_g`, `f_g ≤ Σ credit·x`, 목적함수 `max Σ f_g`. 최대화라 솔버가 `f_g = min(...)`으로 맞춘다(binary·big-M 불필요, 표준 기법). `recommender/model.py`.
- **해석**: 이미 채운 영역(need=0)은 기여 0, 부족 영역은 **부족분까지만** 기여(초과분 무보상).
- 부족분 비례(방식 ②)는 부족분 압도 영역만 계속 추천되는 문제가 있어 미채택. min-cap이 그 절충(필요량까지 동일 보상)이다.

### 4.4 trade-off 보정 (ε 완화)

우선순위형은 1순위를 절대 우선하므로 trade-off가 거칠 수 있다(직무적합 미세 이득을 위해 졸업진척을 크게 포기). 또한 1순위 최적해가 사실상 유일하면 2순위가 개입할 여지가 없다. 이때 약한 우선순위를 적용한다.

```
CareerFit ≥ (1 − ε) · V*       (직무적합을 최대 ε만큼 양보 허용)
```

ε은 "직무적합을 최대 몇 % 양보할 것인가"라는 해석 명확한 비율이라 설정 근거를 대기 쉽다(λ 같은 정체불명 값과 대비). 단, ε은 순수 우선순위(ε=0)로 먼저 실행해 trade-off가 실제로 문제될 때만 도입한다.

**졸업 우선의 영역 가중 (#53)**: ε만 다르게 두면 균형(0.3)과 졸업 우선(0.6)이 같은 시간표를 냈다(학번별 샘플 5개 × 직무 6개 = 30/30). GradProgress의 최대는 학점 상한 U라, 균형에서 이미 담은 학점 전부가 남은 요건에 들어가면 하한을 더 풀어도 더 나은 해가 없다. 그래서 졸업 우선만 2순위 목적을 영역 가중합으로 바꾼다.

```
졸업 우선의 2순위 목적 = Σ_g a_g · f_g      a = 전공필수·교양필수 3, 전공기초·MSC·전공선택 2, 나머지 1
```

- 가중은 목적식에만 건다. 화면의 「졸업 반영」(Result.gradprogress)은 성향과 무관하게 Σ f_g 학점 그대로다.
- a_g가 정수라 서로 다른 해의 가중합 차이도 0이 아니면 최소 1이다. 3순위 δ·CareerFit(폭 ≤ 0.5)의 논증이 그대로 선다.
- 결과: 30/30 모두 균형과 다른 시간표가 되고 졸업 반영은 줄지 않는다(전부 18). 직무 적합은 평균 36%, 최대 59% 낮아지며 ε=0.6 하한 안이다. 예: 산데공 1학년 데이터 분석가는 MSC 4 → 13학점, 경영 1학년은 전공필수 3 · 전공기초 6 · 교양필수 3학점을 먼저 담는다.

## 6. 전체 모델 요약

```
■ 결정변수
   x_c ∈ {0,1}        분반 c 선택 여부,  c ∈ C
                      C = course_section ⋈ course, dept∈{IDE,BIZ,COMMON} ∧ area≠일반선택
                          (≈235과목/762분반)

■ 사전계산 파라미터 (성적표 + DB)
   grade_factor(c) = grade_c/4.5  (P/N→1.0, 미상→0.67)
   σ_k     = 1 − exp(−α · Σ_{기수강 c} grade_factor(c)·w_{c,k})
   gap_k   = max(0, ρ_k − σ_k)
   Score_c = Σ_k gap_k · w_{c,k}
   need_g  = max(0, min_credits_g − 기이수학점_g)   (dept별 grad_req 영역, 일부 제외)
   선수미충족(c) = (선수 p_c 존재 ∧ p_c ∉ 기수강)     (B2용 사전계산 집합)

■ Hard 제약 (1·2순위 공통)
   A1  Σ_{c∈슬롯s} x_c ≤ 1          (모든 슬롯 s; time_slots NULL 분반은 자동 제외)
   A2  Σ_{c∈과목m} x_c ≤ 1          (모든 과목 m)
   A3  Σ_c credit_c·x_c ≤ U         (U = 18 또는 21)
   A3′ Σ_c credit_c·x_c ≥ L         (L = 12)
   B1  x_c = 0                       (기수강 c)
   B2  x_c = 0                       (선수미충족 c)
   B3  x_c = 0                       (공강 요일에 수업이 있는 c; 공강을 고른 경우만)

■ 목적함수 (우선순위형 목표계획법)
   [1순위] max CareerFit(x) = Σ_c credit_c·Score_c·x_c
           → V*
   [2순위] max GradProgress(x) = Σ_g min(need_g, Σ_{c∈g} credit_c·x_c)   (need-cap, f_g 선형화)
           s.t. CareerFit(x) ≥ (1−ε)·V*        (ε=0 기본)
                + 모든 hard 제약
   [3순위] 2순위가 같으면 CareerFit 이 높은 쪽
           → 2순위 목적을 GradProgress + δ·CareerFit 으로 푼다. δ = 0.5 / (U · max_c Score_c)
```

**실행 절차**: ① 파라미터 사전계산 → ② 1순위 ILP 풀어 V* 확보 → ③ V*(또는 (1−ε)V*)를 제약으로 추가 → ④ 2순위 ILP 풀어 최종 시간표 산출.

**3순위가 필요한 이유 (#45)**: 2순위는 CareerFit 을 하한으로만 건다. 하한 위에서 GradProgress 가 같은 해는 목적함수 값이 똑같아서 그중 무엇이 나올지를 CBC 탐색 순서가 정했다. 탐색 순서는 CBC 빌드·플랫폼마다 달라 같은 입력이 로컬(Windows)과 배포 서버(Linux)에서 다른 시간표를 냈다. 더 나쁜 건 **같은 졸업 반영에 직무 적합만 더 낮은 해**, 즉 지배당하는 해가 나올 수 있었다는 점이다. 샘플 성적표로 직무 6 × 성향 3 × 학과 2 = 36개 조합을 재 보니, 3순위를 넣은 뒤 졸업 반영은 36개 모두 그대로이고 직무 적합은 23개에서 올랐다(떨어진 곳 0).

**δ 가 1·2순위를 뒤집지 않는 이유**: GradProgress 는 학점 단위라 서로 다른 해의 차이가 0 이 아니면 최소 1 이다. CareerFit ≤ U·max Score 이므로 δ·CareerFit 의 폭은 0.5 를 넘지 않는다 — 직무 적합을 아무리 올려도 졸업 반영 1학점을 사지 못한다. `tests/test_tie_break.py` 가 이 성질을 고정한다.

**부수 효과 — 성향이 겹칠 수 있다**: 균형(ε=0.3)에서 이미 졸업 반영이 최대치에 닿으면, 졸업 우선(ε=0.6)은 하한만 더 느슨할 뿐 고를 해가 같다. 위 36개 조합에서 12개 (학과, 직무) 중 10개가 그렇다. 전에는 두 성향이 달라 보였지만 그 차이는 졸업 우선이 지배당하는 해를 고른 결과였다.

## 7. 데이터 파이프라인 주의사항

설계(모델)는 후보집합·매핑 데이터가 바뀌어도 불변이다. 단 입력 데이터 준비 단계에서 다음을 처리한다.

1. **과목-역량 매핑 확대(192→3304)**: 2020~2026 누적분이라 동일 과목이 연도별로 중복될 수 있다. **course_id(또는 과목명+학과) 기준 dedupe**하여 과목당 대표 1행으로 정리(σ 계산 시 중복 가산 방지).
2. **relevance 가중 (매핑 05)**: 정규화(합=1)만 쓰면 데이터 무관 과목(미술·어학 등)이 한 역량에 weight를 몰아 진짜 데이터 과목을 추월하는 **순위 역전**이 생긴다(예: 드로잉 VIZ > 데이터시각화 VIZ). 이를 막기 위해 과목별 **relevance r_c = 1−exp(−rawТ/τ)** 를 곱해 weight 합을 r_c(≤1)로 만든다. 무관 과목은 r_c≈0 → 전 역량 기여 ≈0. 부수효과로 **σ 과대포화도 완화**(무관 과목이 σ를 부풀리지 않음).
3. **타 학과 과목 처리**:
   - 역량 매핑: 학과 불문 전부 수행(무관하면 relevance↓로 자동 0에 수렴).
   - σ 계산: 기수강이면 학과 불문 전부 반영(relevance가 무관 과목 기여를 자동 축소).
   - 후보집합 C: catalog 확장 후 DB의 course는 전체 universe이므로 **ILP 쿼리에서 명시 필터**(dept∈{IDE,BIZ,COMMON} ∧ area≠일반선택). 타학과 전공은 merge에서 일반선택으로 환산돼 있어 이 필터로 배제됨.
   - 기이수학점(need): merge 의 환산은 지원 학과 **밖**의 전공만 덮는다. IDE·BIZ 는 서로 타 학과인데도 각자 영역을 유지하므로, 학생 학과 기준 환산을 `data.load_student` 에서 한 번 더 한다(#40).
4. **매핑 재생성 후 재검증**: 매핑은 모델 입력이므로 변경 시 σ·Score 결과가 달라진다. 샘플 학생으로 추천 타당성을 재확인한다.

## 8. 명시할 한계 (발표/문서용)

- **σ·gap 스케일**: ρ와 σ의 0~1이 엄밀히 동일 척도가 아니며, gap은 순위용 상대점수로만 사용. 역량 간 합산 스케일 차이는 민감도 분석으로 방어.
- **σ unmatched**: catalog에 역량매핑(w)이 없는 기수강 과목(pre-2020 폐지·크롤 밖)은 σ에 0 기여 → σ 과소→gap 과대 편향 가능. catalog 3,304 확장으로 매칭률은 최대화. need_g는 fallback area로 학점 집계되므로 σ와 처리 비대칭이 있음.
- **선수과목**: hard 차단(B2). 후보집합 안에서는 데이터 완전하나, 단일 course_id 스키마라 OR·복수(AND) 선수조건 미지원(현 14건은 단일 체인).
- **P/N 처리**: P/N을 A+(1.0)로 관대 인정 → σ가 소폭 낙관 편향. 과목 수가 적고 대개 교양이라 영향 작음.
- **졸업요건**: 특성화교양·SW데이터활용역량·교양총합 cap 미반영(UI 명시). 영역별 하한 cap은 need-cap(min)으로 반영됨(4.3.1). dept별 grad_req의 하한 영역만 반영(IDE 7개, BIZ는 area 구성 다름 — 동적 도출).
- **졸업 페이스**: "남은 학기" 기반 페이스 제약 미반영(진척 유도로 대체). 고도화 대상.
- **성적 예측 미수행**: 추천 후보 과목의 미래 성적은 예측하지 않음(존재하지 않는 데이터).

## 9. 튜닝·검증 항목

- **튜닝**: α(σ 곡선), ε(완화 여유), U/L, K(과목별 기여 역량 수 — `recommender.diagnose`로 변별력·1학년 추천을 같이 잰다). (grade_factor는 grade/4.5로 고정, 선수는 hard라 μ_pre 없음.)
- **민감도 분석**: α·ε 변화에 따른 추천 변동 측정 → 견고성 입증(가중치 임의성 방어).
- **베이스라인 비교**: LLM 프롬프팅 대비 제약 위반율(0% 보장)·재현성 비교.
- **샘플 검증**: 대표 학생(학년·직무별)로 추천이 직관에 부합하는지 확인.
