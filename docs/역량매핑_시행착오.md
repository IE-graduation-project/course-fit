# 역량 매핑 — 시행착오와 성능 개선

과목·직무를 10차원 역량 벡터로 매핑(`docs/과목과직무_역량_매핑.md`)하는 과정에서,
초기 산출물이 사실상 "변별력 없는 균등분포"에 가까웠다. 검증 → 원인 진단 → 수정의
반복으로 변별력을 끌어올린 기록이다. (2026-05-27)

## 0. 한 줄 요약

| 단계 | 과목 평균 엔트로피 (max 2.303, 낮을수록 변별력↑) | top1 weight 평균 (0.10=균등) |
|------|------|------|
| 초기 | 2.203 (96% of max) | 0.196 |
| 키워드 버그 수정 + 행 단위 정규화 | 1.933 | 0.301 |
| α 튜닝 + OR 키워드 정리 | **1.792** | **0.383** |

직무 벡터는 버그 수정만으로 `docs/역량_taxonomy_근거.md`의 설계 의도(직무별 중심 역량)와
거의 정확히 일치하게 되었다.

## 1. 증상 — 벡터가 너무 평평하다

초기 `course_competency.csv`를 검증하니 과목별 10개 역량 weight가 균등(0.10)에 가까웠다.
- 평균 엔트로피 2.203 = 최대치(ln 10 = 2.303)의 96%.
- top1 weight 평균 0.196 → 1위 역량조차 균등 대비 2배 수준에 불과.

"데이터사이언스가 DATA·ML에 뾰족하게 매핑"되길 기대했으나, 모든 과목이 비슷하게 퍼졌다.

## 2. 진단 도구 — 엔트로피로 변별력 측정

벡터의 "뾰족함"을 엔트로피로 정량화했다. 확률분포 `p`(weight 정규화)에 대해
`H = −Σ pᵢ log pᵢ`. 균등분포에서 최대(ln 10), 한 역량에 집중될수록 0에 가깝다.

이를 **성분별로 분리**해 보니 원인이 드러났다:

| 성분 | 평균 엔트로피 | 해석 |
|------|------|------|
| TF-IDF 단독 | **0.574** | 매우 뾰족 — 변별력 우수 |
| KoSBERT 임베딩 단독 | **2.279** | 거의 균등 — 변별력 없음 |
| 결합(α=0.5) | 2.203 | 평평한 임베딩이 날카로운 TF-IDF를 희석 |

→ **KoSBERT 임베딩이 범인.** 한국어 짧은 텍스트에서 모든 역량과의 코사인 유사도가
좁은 고밀도 band에 몰리는 **anisotropy** 문제. 역량 간 차이가 거의 생기지 않는다.

## 3. 버그 — ASCII 짧은 키워드의 부분문자열 거짓 매칭

직무 벡터에서 데이터 분석가(DA)의 `OR`(경영과학)이 **1.0(최대)** 으로 나왔다.
데이터 분석가에 운영연구가 최상위일 리 없다.

원인: TF-IDF의 키워드 매칭이 **소문자 부분문자열** 방식이라, OR 키워드 사전에 있던
영어 두 글자 `"OR"`가 영단어 내부에 마구 매칭됐다.

```
DA 공고 20건: 'or' 부분문자열 185회  vs  진짜 한국어 OR 키워드 6회
              (w·or·k, f·or, rep·or·t, c·or·hort ...)
```

`"AI"`도 tr·ai·ning, m·ai·n, em·ai·l 등에 매칭되어 ML을 부풀렸다.

**수정**(`mapping/03_compute_tfidf.py`): ASCII 키워드는 **단어 경계 매칭**(앞뒤가
영문·숫자가 아닐 때만), 한국어 키워드는 기존 부분문자열 유지.

```python
# (?<![a-z0-9]) keyword (?![a-z0-9])  ← 'or'가 work/for 안에서 매칭되지 않음
```

> 한국어 과목 설명에는 'or'/'ai'가 거의 없어 과목 쪽 영향은 작았지만,
> 영어가 많은 직무 공고에서는 치명적이었다.

## 4. 정규화 — 전역 min-max → 행 단위 min-max

두 점수(TF-IDF·임베딩)를 결합 전 min-max로 스케일을 맞췄는데, 처음엔 **행렬 전체**
기준이었다. 이러면 극단적인 한두 문서가 전체 스케일(min/max)을 독점하고, 나머지
문서의 역량 간 차이가 상대적으로 짓눌린다. 특히 분산이 작은 임베딩에서 치명적.

**수정**(`mapping/05_combine_normalize.py`): **행(문서) 단위 min-max**로 변경.
각 문서를 독립적으로 0~1로 펴서, 그 문서 내부의 "어느 역량을 더 선호하는가" 구조를 보존.

→ 임베딩 단독 엔트로피 2.279 → 2.029, 결합 2.203 → 1.933.

> 참고: 행 중심화(per-row centering)도 시도했으나 효과 미미(2.279→2.235). 전역 스케일
> 독점이 더 근본 원인이었다.

## 5. 튜닝 — α 상향 + OR 키워드 정리

남은 문제 두 가지:
1. `OR`이 거의 모든 과목 top3에 등장(국제경영 OR 2위 등) — OR 정의·키워드가 포괄적이라
   임베딩이 광범위하게 유사하다고 판단.
2. 평평한 임베딩이 여전히 절반(α=0.5)을 차지.

**조치 A — α 0.5 → 0.7**: `combined = α·tfidf + (1−α)·sim`에서 TF-IDF 비중↑.
설계 문서가 이미 α를 조정 가능한 상수로 명시.

**조치 B — OR 키워드 정리**: 범용어 `최적화`, `OR`, `제약조건`, `목적함수`를 제거하고
`수리최적화`, `정수최적화` 등 OR 고유어만 남김. 정의문도 `의사결정`(범용) 제거.

→ 평균 엔트로피 1.933 → 1.792, top1 평균 0.301 → 0.383.
   OR이 top3에 드는 과목 "거의 전부" → 69/193, OR 1위 과목 17 → 11.

## 6. 결과와 수용한 트레이드오프

**직무 벡터 (발표 가능 품질)** — 설계 의도와 일치:

| 직무 | 산출 top3 | 설계 의도 중심 역량 |
|------|----------|------|
| DA | VIZ, DATA, BIZ | DATA, VIZ |
| DE | DB, PROG, ML | DB, PROG |
| DS | ML, PROG, DB | ML, DATA, PROG |
| FIN | FIN, BIZ, COMM | FIN, DATA |
| MKT | MKT, BIZ, COMM | MKT, BIZ |
| PM | BIZ, COMM, PROG | BIZ, COMM |

**과목 벡터** — 1위 역량 전부 정확(데이터사이언스→DATA, 회계원리→FIN, 마케팅→MKT,
DB기초→DB, 기계학습→ML).

**수용한 트레이드오프:**
- `최적화` 키워드를 빼면서 `데이터기반최적화` 과목이 OR가 아닌 PROG/DATA 우위로. 거짓 OR
  17→11과 맞바꾼 순이득으로 판단(데이터기반 최적화라 PROG/DATA도 오답은 아님).
- `국제경영` OR 0.24 등 임베딩 잔여 아티팩트는 남음. argmax가 정확하므로 sanity check
  통과로 간주(설계 8절 "결과 육안 검토" 취지).

## 7. 배운 점

- **합성 점수는 성분별로 분해해 측정하라.** 결합 점수만 봤으면 "임베딩이 평평하다"를
  못 짚었다. 엔트로피를 성분별로 분리한 게 결정적이었다.
- **부분문자열 매칭 + 짧은 ASCII 키워드 = 거짓 매칭 지뢰.** 다국어 텍스트일수록.
- **min-max는 "무엇을 기준으로"가 결과를 가른다.** 전역 vs 행 단위의 차이가 컸다.
- KoSBERT는 의미 보강엔 유용하나 anisotropy 탓에 단독 변별력은 약함 → TF-IDF에 더 무게.
