## 4. 선정 기준 (가이드 3개 기준 적용)

### (1) 빈도
- 4개 직무 모두 **20건 이상**으로 통계적 매핑 신뢰도 확보
- 가장 적은 DA(49)도 가이드 권고 최소치(20)의 2.4배

### (2) 학과 적합도 — 산업데이터공학과·경영학과
- **DA / PM**: 두 학과 모두 진로 적합 → 공통 추천 대상
- **DS**: 산데공 강점 (통계·ML·프로그래밍 역량 ↔ ML/AI 엔지니어 수요)
- **MKT**: 경영 강점 (경영전략·소비자행동 ↔ 브랜드/퍼포먼스 마케터)

### (3) 직무 간 역량 차별성
`data/competency.csv` 의 10개 역량(PROG, DATA, ML, DB, VIZ, BIZ, FIN, MKT, OR, COMM)으로 봤을 때:

| 직무 | 중심 역량 | 보조 역량 |
|------|----------|----------|
| DA | DATA, VIZ | PROG, DB, COMM |
| DS | ML, PROG | DATA, OR |
| PM | BIZ, COMM | DATA, PROG |
| MKT | MKT, BIZ | COMM, DATA |

→ 4개 직무가 서로 다른 중심 역량을 가지므로 ILP 추천 시 학생 역량에 따라 차별화된 결과 도출 가능. 자세한 taxonomy 근거는 `docs/역량_taxonomy_근거.md`.

## 6. 매핑 방법 — 휴리스틱 + 수작업 큐레이션

`mapping/job_decision.py` 구현 요약:

### 단계
1. **추출**: `raw_text` 첫 segment에서 `[회사명]` `[부서]` 등 대괄호 토큰 제거
2. **Fallback**: 첫 segment가 부서명/일반 단어(`Tech`, `토스코어` 등)면 `직무:` `직군:` `직무 카테고리:` `채용분야:` `포지션:` 라벨에서 추출
3. **풀모집 차단**: `인턴십 모집 (마케팅, HR, ...)` `공개채용 (... 외)` `부문별 경력사원 채용` `인재 pool` `talent pool` 등 다중직무 공고는 무조건 None (한 공고에 여러 직군이 묶이면 통계 왜곡)
4. **정규화**: 소문자 + 공백/구두점 제거
5. **분류**: title-only 키워드 부분일치. 우선순위 DA > DS > PM > MKT
6. **부정 키워드**: false positive 차단
   - DA: `security` `compliance` `financialanalyst` `vulnerabilityanalyst` 등 (보안/재무 분석가 분리)
   - DS: `backend` `frontend` `ios` `android` `aml`(Anti-Money Laundering ≠ AI) `infrastructure` `devops` `designer` `compiler` 등
   - PM: `md` `merchandiser` `현장pm` `건설pm` `조선` `안전관리`, 그리고 게임 도메인 기획자(`게임기획` `전투기획` `밸런스기획` `시스템기획` `레벨디자인` `BM기획` `설정기획자` 등) 일괄 제외
   - MKT: `designer` `디자이너` `크리에이터` `creator` `사무보조` `marketingdesigner` 등
7. **Override (수작업 큐레이션)**: `mapping/job_decision_overrides.csv` (`posting_url,job_id,reason` 헤더)에 명시된 row는 휴리스틱 결과를 덮어쓴다. `job_id=NONE`이면 강제 미분류.

**raw_text 본문 매칭은 의도적으로 끔.** 본문에 "데이터 분석" 등이 언급된 다른 직무(예: 마케터)가 DA로 오분류되는 false positive를 차단하기 위함.

### 키워드 보강 라운드별 변화

| 라운드 | DA | DS | PM | MKT | 합계 | 비고 |
|--------|----|----|----|-----|-----|------|
| 1차 (본문 매칭 포함) | 147 | 179 | 123 | 89 | 538 | 표본 검증 시 본문 매칭 false positive 다수 — Polish marketer가 DA로, QA Team Leader가 DS로 분류됨 |

| **3차 (키워드·부정어·풀모집 차단 보강, 최종)** | **63** | **147** | **139** | **151** | **500** | UNMAPPED 303건 수작업 분류 후 키워드 추가, 게임 도메인/AML 차단 |

## 7. 향후 보강 옵션 (선택)

현재 미매핑 3,326건 중 대부분은 우리 4개 직무 외(SW Engineer, 디자이너, 보안, 기간제 등). LLM 추가 호출의 ROI는 낮은 상태.

추가 매핑 필요 시:

```bash
# (옵션 1) override.csv에 직접 추가
echo "https://...,DA,수작업 분류" >> mapping/job_decision_overrides.csv

# (옵션 2) Claude/Codex/Gemini 등을 통해 직접 분류 후 override 머지
# (옵션 3) OpenAI API 사용 — .env에 OPENAI_API_KEY 추가 후
python -m mapping.job_decision --llm --llm-limit 500
```

> LLM 호출은 비용을 발생시키므로 본 시스템에서는 휴리스틱(키워드 사전 + 부정 키워드 + 풀모집 차단) + 수작업 override 조합으로 충분히 정확도를 확보했음. UNMAPPED 잔여분은 대부분 우리 4개 직무 외 직군이므로 추가 매핑 가치 낮음.

## 9. 발표 방어 논리

> "대상 직무 4개(데이터 분석가 DA, 데이터 사이언티스트 DS, 프로덕트 매니저 PM, 마케팅 매니저 MKT)는 크롤링한 3,826건 채용공고의 직무명 빈도 분석을 기반으로 선정했다. 빈도 상위 직무 중 (i) 두 학과(산업데이터공학과·경영학과) 진로 적합도, (ii) 10개 역량 taxonomy에 따른 직무 간 차별성, (iii) 직무별 최소 20건 이상의 통계적 매핑 신뢰도 — 세 기준을 모두 충족하는 직무를 채택했다. 매핑은 title-only 휴리스틱(키워드 사전 + 부정 키워드 + 풀모집 차단) + 수작업 override 조합으로 진행했으며 총 500건(13.1%)을 매핑했다. 표본 60건 정확도 검증 결과 98% 이상의 정밀도를 확인했고, 본문 매칭으로 인한 false positive를 차단하기 위해 보수적 전략을 택했다."
