# course-fit UX 철학 (최종)

> 발표/팀 공유용. 6렌즈 병렬 리서치 → 1차 종합 → 디자인 디렉터 적대적 비판 → 최종 수렴으로 도출한 확정본. 비판에서 지적된 복잡성은 덜어내고, 숨긴 결정은 다시 꺼내 보이게 했다.
>
> 업데이트(2026-06-09, 제품 오너 결정): 목표 직무는 “자동 추천 기본값”이 아니라 학생이 직접 고르는 “명시적 선택”으로 확정. 리서치가 권고한 Visible Default(자동 추천기) 대신, 설계 문서 정합성과 발표 방어 용이성을 우선해 직접 선택을 채택한다. 아래 결정 [a]와 사용자 흐름은 이 결정을 반영해 갱신함. 자동 추천기는 향후 확장 옵션으로만 남긴다.

## 1. UX 철학 (북극성 = 단순함)

course-fit의 단순함은 “화면 단계를 줄이는 것”이 아니라 “학생이 내려야 할 결정을 정직하게 보여주되, 그 결정을 쉽게 만드는 것”이다. 성적표를 붙여넣으면 충돌 없는 다음 학기 시간표가 즉시 떠오르고, 목표 직무는 시스템이 먼저 제안하되 화면 맨 위에서 학생이 한 번에 바꿀 수 있게 보인다. 우리는 복잡성을 사용자 눈 밖으로 숨겨 단순한 척하지 않는다. 보여줄 결정은 크고 명확하게 보이고, 안 보여도 되는 계산(ILP, 점수 수식)만 접는다. 실제 사용자는 학생이며, 심사위원의 신뢰는 예쁜 보더가 아니라 결과의 정확성과 투명성으로 얻는다.

## 2. 핵심 원칙 (5개)

원칙 1. 그리드와 “왜”가 함께 있을 때만 증명이다.
색상으로 채워진 주간 그리드가 추천의 결과를 보여주지만, 추천형 제품에서 빈칸 없는 그리드는 그 자체로 신뢰가 아니라 의심의 출발점이다. 왜 이 과목인지 한 줄이 붙어야 비로소 증명이 된다. (학생이 직접 고른 에브리타임 그리드와 달리, 시스템이 고른 그리드는 근거 없이는 불신을 부른다.)

원칙 2. 입력은 paste 하나, 보여줄 결정은 직무 하나.
성적표 붙여넣기가 곧 시작이다. 학점은 기본값(18학점)으로 접고, 직무만 화면 맨 위에 명시적으로 보이는 변경 가능한 기본값으로 띄운다. 결정 포인트를 줄이되, 가장 중요한 결정(목표 직무)은 숨기지 않는다.

원칙 3. 인식은 그 자리에서 즉시 보여주고, 실패도 그 자리에서 복구한다.
붙여넣기 직후 textarea가 idle → parsing → recognized로 전환되고, “N과목 인식, X학점, GPA Y”와 함께 부분 인식/실패가 그 자리에서 드러난다. 오류를 결과 화면까지 끌고 가지 않으며, 깨진 줄은 복구 경로를 같이 준다.

원칙 4. 설명은 “있다는 사실 + 한 줄 근거”로 충분하다.
역량 레이블 한 줄, 근사 반사실 한 줄(“약 -18pt”), 충돌 0 뱃지. 이 셋으로 끝낸다. ILP 수식, 점수 테이블, 가중치 슬라이더는 신뢰를 올리지 않거나 떨어뜨리므로 기본에서 뺀다.

원칙 5. 제거가 기본 동작이고, 결과 화면에도 똑같이 적용된다.
새 요소는 “이게 더 단순해지나”를 통과해야 추가된다. 입력만 줄이고 결과 화면에 다 쌓아두는 건 치운 게 아니라 미룬 것이다. 결과는 그리드 + 직무 토글 + 한 줄 요약으로 끝낼 수 있는지 먼저 증명하고, 못 끝낼 때만 추가한다.

## 3. 확정 결정 (5가지)

[a] 목표 직무: 학생이 직접 고른다 (명시적 선택). 자동 추천 기본값은 쓰지 않는다.
6개 직무를 한 줄 설명과 함께 카드로 보여주고 학생이 고른다. 이는 설계 문서 정의(“학생이 목표 직무를 고르면”)와 정확히 일치하고, 별도 직무 추천 알고리즘을 만들고 방어할 필요가 없어 발표에 유리하다. ILP는 “시간표만 푼다”로 설명이 깔끔해진다.
- 진로 미정 학생: 카드 옆에 “잘 모르겠어요”를 둔다. 누르면 이수 과목 기반으로 “데이터 쪽이 가까워요” 힌트만 주고, 최종 선택은 학생이 한다(자동으로 정해버리지 않음). 6개가 부담되면 데이터/비즈니스/금융 3방향으로 먼저 좁혀도 된다.
- switch and see: 첫 시간표 생성 후 결과 화면 상단 직무 토글로 다른 직무를 눌러 비교할 수 있다. 선택은 입력 단계에 두되, 탐색은 결과에서 이어진다.
- 메커니즘 정직하게 표기: 시간표 “최적화”가 ILP다. “ILP가 직무를 고른다”고 말하지 않는다(직무는 학생 입력).
- 향후 확장(현 범위 밖): 이수 과목 분포 기반 경량 직무 추천기를 더해 기본값을 제안할 수 있으나, 이는 별도 알고리즘이라 발표 범위에서 분리한다.

[b] 단계 수: 단일 화면 + 순차 공개(progressive disclosure).
필드 3개짜리 제품에 마법사식 다단계는 마찰만 늘린다. 단일 화면을 유지하되 성적 인식이 끝난 뒤 직무 영역이 나타나는 순차 공개로 부하를 낮춘다.

[c] 성적표 온보딩/인식 확인: 비자격증명 카피 + 칩 단위 경량 확인 + 구조적 실패 폴백.
“로그인 정보 수집 없음, 텍스트만 붙여넣으면 됩니다” 한 줄. 파싱은 붙여넣기/포커스 아웃 시 1회 트리거(실시간 검증 금지). 인식 결과는 칩으로, 수정은 칩 X 삭제/+ 추가. 단, 이건 1~2개 오류용이다. 부분/구조적 실패는 [엣지 케이스]에서 별도 폴백으로 처리한다(엑셀형 편집 테이블은 만들지 않음).

[d] “왜”의 노출 수준: 한 줄 × 3, 기본 접힘, 신뢰도는 상대 표시.
과목 카드에 역량 레이블 1줄, 결과 상단에 충돌 0 뱃지 + 근사 반사실 1줄. 깊은 설명은 접고, 신뢰도는 % 대신 높음/보통/낮음으로 준다. 반사실 수치는 정확 재최적화가 아니라 근사(해당 과목 적합도 기여분 차감)이며 “약” 표기로 정직하게 둔다.

[e] 비주얼 톤: instrument-panel을 완화하되, 우선순위는 학생.
밀도/보더 카드/데이터 직접 노출이라는 뼈대는 유지하고, dark → warm-neutral white 배경, mono UI 라벨 → Plus Jakarta Sans(mono는 숫자 데이터에만), sharp edge → 8~12px radius, cool → warm gray(Stone/Zinc) 보더로 온도만 조정한다. 단일 그린 액센트는 CTA/점수 하이라이트에만. 비주얼은 학생 우선으로 정하고, 심사위원 신뢰는 결과 정확성으로 얻는다. 비주얼로 심사위원을 설득하려 하지 않는다.

## 4. 사용자 흐름 (최소 단계)

1. 진입: textarea 하나 + “로그인 정보 수집 없음” 카피.
2. paste: textarea가 recognized로 전환, “22학번 / 98학점 / GPA 3.6 / 24과목 인식” 칩 표시. 부분 실패 시 “20과목 인식, 4과목 확인 필요”와 깨진 줄 하이라이트.
3. 직무 선택: 인식이 끝나면 직무 카드 6개(+ “잘 모르겠어요”)가 나타난다. 학생이 하나 고르면 그 아래 시간표 그리드가 생성. 화면 맨 위에 “데이터 엔지니어 ▾, 충돌 0, 적합도 84”.
4. 조정: 상단 직무 토글로 다른 직무를 눌러 비교(사전 계산된 6직무 해를 캐시 조회). 특정 과목이 싫으면 “이 과목 제외하고 재추천”, “이 시간대 비우기”로 제약을 건다.
5. 결과 확인: 그리드가 답이고, 나머지는 접힌 보조.

핵심 결정 포인트는 단 둘이다: paste, 그리고 직무 선택. 그 외 모든 것은 기본값 또는 시스템 처리.

## 5. 화면별 구성

메인
- 보여준다: 큰 textarea, 비자격증명 카피, 인식 칩(학번/학점/GPA/과목 수), 인식 후 나타나는 추천 직무.
- 숨긴다: 학점 슬라이더(기본 18, “학점 범위 변경” 링크로 접힘), 6지 선다 빈 선택지, ILP/점수/수식 일체.
- 전환: 인식 완료와 함께 같은 화면에서 결과 그리드가 펼쳐진다(별도 페이지 강제 없음).

결과
- first fold: 직무 토글(추천 직무 맨 앞, 변경 가능) + 그리드 + 한 줄 요약(직무 / 충돌 0 / 적합도 84). 과목 블록 탭 시 역량 레이블 1줄 + 근사 반사실 1줄.
- 재최적화 인터랙션: 과목 제외, 시간대 비우기.
- 숨긴다(기본 접힘 또는 제거): 졸업 진척도는 직무 적합 시간표라는 핵심과 직접 관련이 약하므로 기본에서 제거(졸업 임박 모드에서만 등장), 적합도 차트는 상단 한 줄 숫자로 대체하고 레이더/막대 차트는 토글로만, 대안 시간표도 토글.

## 6. 컨셉 방향 (3개) + 추천

컨셉 A — 명시적 기본값 (Visible Default)
- 컨셉: paste 즉시 시스템이 직무를 골라 시간표를 띄우되, 직무를 화면 맨 위에 크고 변경 가능하게 보인다(zero-click 아님, 1-glance default).
- 흐름: paste → 인식 칩 → 추천 직무 + 그리드 자동 생성 → 상단 직무 토글로 바꿔보기.
- 비주얼: Structured Warmth, white 배경, 그리드가 무게중심.
- 성격: 최소 단계 + 투명성을 둘 다 잡음. 단계는 짧지만 결정은 숨기지 않는다.

컨셉 B — 가벼운 명시적 선택 (Guided + Switchboard)
- 컨셉: 직무 6개 대신 “데이터 / 비즈니스 / 금융” 3방향만 먼저 묻고(“모르겠어요”는 진단형 응답으로 분기), 결과 위 칩으로 직무를 갈아끼운다.
- 흐름: paste → 인식 → 3방향(또는 진단) → 그리드 → 결과 상단 직무 칩으로 switch and see.
- 비주얼: Structured Warmth, 3버킷은 낮은 채도 카드.
- 성격: 자동 추천이 틀릴 위험을 학생 선택으로 흡수. 단, 버킷 → ILP 목적함수 매핑(대표 직무 기준)을 명시해야 함.

컨셉 C — 라이브 스위치보드 (Live Switchboard)
- 컨셉: 직무를 입력이 아니라 결과 위 토글로 격하, 시간표를 보며 직무를 갈아끼운다.
- 흐름: paste → 인식 → 즉시 결과 → 상단 직무 칩 바 실시간 전환.
- 비주얼: 직무별 낮은 채도로 과목 블록 구분(적합도는 숫자 뱃지로 분리).
- 성격: 인터랙션 신뢰가 가장 강하나 결과 밀도가 가장 높음. 사전 계산 캐시 전제.

추천: 컨셉 A를 기본으로, 컨셉 B의 명시적 선택 가벼움과 C의 결과 화면 직무 칩 바를 흡수한다.
이유: 비판이 짚은 핵심은 “zero-click은 단순함이 아니라 결정을 숨긴 것”이다. A의 명시적 기본값은 단계를 짧게 유지하면서도 직무를 보이게 해 투명성을 회복한다. 직무 인터랙션은 C의 결과 칩 바로 “바꿔보고 결과를 본다”를 살리되, 실시간 부담은 사전 계산 캐시로 푼다. 자동 추천이 불가능하거나(저학년, 이수 과목 부족) 사용자 테스트에서 “자동 선택이 틀렸다”가 관측되면 B의 명시적 3방향 선택으로 폴백한다. 즉 B는 예비안이 아니라 A가 못 서는 자리(데이터 부족)에서 1급으로 켜지는 폴백이다.

## 7. 엣지 케이스 처리

직무를 전혀 모르는 학생.
“모르겠어요”는 자동 선택으로 우회시키지 않고 진단형으로 응답한다: “이수 과목을 보면 데이터 쪽이 가깝습니다. 데이터 / 비즈니스 / 금융 중 골라볼래요?” 추천 근거를 보여준 뒤 가벼운 선택지로 넘긴다.

성적표 형식이 깨진 경우.
- 부분 인식: “12과목 중 8개 인식, 4개 확인 필요”를 명시하고 깨진 줄을 하이라이트. 칩 삭제/추가로 보정.
- 완전 실패: 폴백으로 학교 선택 → 포맷 템플릿, 또는 수동 입력 최소 양식 제공. 지원 학교 포맷을 명시한다. 칩 편집은 1~2개 오류용이지 구조적 실패의 해결책이 아니다.

졸업 임박 학생.
잔여 졸업요건이 직무 적합도보다 급하다. 졸업학점/잔여요건을 입력 신호로 받아 “졸업요건 우선” 모드로 전환하고, 이때만 졸업 진척도를 전면에 띄운다.

저학년 / 이수 과목 부족.
자동 직무 추론에 필요한 최소 이수 과목 수(예: 5과목)를 정의하고, 미만이면 자동 추론을 끄고 명시적 직무 선택(컨셉 B 흐름)으로 폴백한다. 데이터 없는 추측을 추천으로 포장하지 않는다.

추천이 마음에 안 드는 경우.
직무는 맞는데 특정 과목이 싫을 때를 위해 “이 과목 제외하고 재추천”, “이 시간대 비우기” 두 제약을 제공한다. 갈 곳이 “다른 직무 누르기”뿐인 막다른 골목을 없앤다. ILP 제품인 만큼 최소한의 제약 추가는 핵심 가치다.

계산 비용/실시간성.
직무 칩 전환을 실시간으로 약속하므로, 6직무 해를 사전 계산(precompute)해 캐시 조회로 처리한다. 재최적화(과목 제외 등)는 상한 시간을 두고, 초과 시 근사해 + “최적 근접” 표기로 정직하게 처리한다. 반사실 수치도 정확 재최적화가 아닌 근사이며 “약”으로 표기한다.
