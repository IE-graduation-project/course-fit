# 추천 근거 설명 — 화면의 숫자는 무엇이고 어떻게 나왔나

발표/시연에서 `--explain` 출력의 소수들을 질문받을 때 쓰는 설명 자료.
모든 숫자는 σ → gap → Score → ILP 한 줄기에서 나온다(블랙박스 아님).
근거 설계: `docs/ILP_추천시스템_설계.md`.

---

## 화면 숫자 5종류

### ① σ — "이미 갖춘 역량" (예: 프로그래밍 0.91)
학생이 *현재* 보유한 역량 추정치(0~1), 역량별.
```
σ_k = 1 − exp( −α · Σ_{기수강 c} grade_factor(c) · w_{c,k} )
```
- `w_{c,k}`: 과목이 역량 k에 기여하는 비중 (course_competency, 매핑 산출)
- `grade_factor = 성적/4.5` (A+ 1.0, B+ 0.78 …)
- `α = 1.5`: 포화 곡선. `1−exp`는 같은 역량 과목을 많이 들을수록 1에 수렴(수확체감).

### ② gap — "채워야 할 역량" (예: 데이터시각화 0.39)
목표 직무 요구 대비 부족한 만큼. `gap_k = max(0, ρ_k − σ_k)`

DA 직무 기준 실제값:
| 역량 | ρ(직무요구) | σ(학생보유) | gap=max(0,ρ−σ) |
|------|---:|---:|---:|
| 데이터시각화 | 1.00 | 0.61 | **0.39** |
| 비즈니스 | 0.95 | 0.65 | **0.30** |
| 데이터베이스 | 0.83 | 0.57 | **0.26** |
| 데이터분석 | 0.95 | 0.82 | **0.13** |
| 프로그래밍 | 0.18 | 0.91 | 0.00 (충족) |

`max(0,·)`: 이미 충족(σ≥ρ)이면 0 → 그 역량 과목은 추천에서 자동 디스카운트.

### ③ 과목별 % — "이 과목이 어느 갭을 채우나" (예: DB 61%)
```
Score_c = Σ_k gap_k · w_{c,k}            (과목의 직무적합도)
표시 %   = (gap_k · w_{c,k}) / Score_c
```
데이터베이스설계 (Score=0.161) 실제 분해:
| 역량 | gap | × w | = 기여 | 비중 |
|------|---:|---:|---:|---:|
| 데이터베이스 | 0.26 | 0.381 | 0.099 | **61%** |
| 데이터시각화 | 0.39 | 0.072 | 0.028 | **17%** |
| 데이터분석 | 0.13 | 0.196 | 0.025 | 16% |

해석: "네가 약한 DB(gap 0.26)를 이 과목이 크게 다뤄서(w 0.38) 점수의 61%가 DB 보완."

### ④ need — "남은 부족 학점" (예: 전공선택 42)
졸업까지 그 영역에서 더 들어야 하는 학점.
`need_g = max(0, min_credits_g − 기이수학점_g)`
- `min_credits_g`: 졸업요건 영역별 최소학점 (graduation_requirement)
- `기이수학점_g`: 성적표를 영역별 합산 (student_course)

### ⑤ ε=0.3 — "성향 손잡이"
1순위(직무적합)를 최대 ε만큼 양보하고 2순위(졸업진척)를 챙기는 여유.
2순위 풀 때 `CareerFit ≥ (1−ε)·V*`. balanced 프리셋 = 0.3.

## 한 과목이 추천되는 전체 사슬

```
성적표 ──▶ σ (보유)    프로그래밍 0.91, DB 0.57
직무 DA ─▶ ρ (요구)    시각화 1.0, DB 0.83
           gap = max(0, ρ−σ)   DB 0.26 (부족)
                 │
과목 weight ─▶ Score = Σ gap·w   데이터베이스설계 0.161 (DB 61%)
                 │
           1순위 ILP  max Σ credit·Score·x      → 선택
           2순위 ILP  졸업진척(need-cap)         → 전공선택 42부족이라 +
           제약       시간충돌·학점·기수강·선수
                 ▼
           "데이터베이스설계 — DB 갭 61% 보완 + 전공선택 졸업학점"
```

## ⚠️ 중요 — ρ와 σ는 "동일 척도"가 아니다 (정직한 한계, 자주 받는 질문)

`gap = ρ − σ`로 1:1 빼지만, **두 0~1의 의미가 다르다.**

| | ρ_k (직무 요구) | σ_k (학생 보유) |
|---|---|---|
| 출처 | job_competency | 성적표 기반 σ 식 |
| 정규화 | **직무별 min-max** (그 직무에서 가장 중시 역량=1.0, 최소=0.0) | **포화 누적** (안 들으면 0, 많이 들으면 1) |
| 0~1 의미 | "이 직무가 *상대적으로* 얼마나 중시하나" (순위) | "학생이 *절대적으로* 얼마나 쌓았나" (양) |

즉 ρ=1.0은 "100% 숙련 요구"가 아니라 **"이 직무의 최우선 역량"**이고, σ=0.61은 "그만큼 쌓았다"는 절대량. **둘은 엄밀히 같은 자가 아니다.**

**그래서 우리 설계는 gap을 "절대 부족량"이 아니라 "순위용 상대점수"로만 쓴다** (설계 §4.2.1 방식 Y, §8).
- 필요한 성질은 단조성 둘뿐: 직무가 중시할수록(ρ↑) gap↑, 학생이 잘할수록(σ↑) gap↓. **뺄셈이 이 둘을 보존**한다.
- gap의 절대값(0.39)에 물리적 의미를 부여하지 않는다. **"39% 부족"이 아니라 "이 직무에서 네 최대 상대 갭"**으로 읽는다.
- 역량 간 합산(Σ_k)의 스케일 차이는 한계로 인정하고, **α 민감도 분석**으로 추천 안정성을 확인해 방어한다.

**발표 멘트 예**: "ρ는 직무별 상대 중요도, σ는 학생의 누적 숙련도라 단위가 완전히 같진 않습니다. 그래서 gap을 절대 부족량이 아니라 *과목을 줄 세우는 순위 신호*로 사용합니다. 필요한 건 '직무가 중시하고 학생이 약한' 방향성이고, 뺄셈이 그걸 보존하기 때문에 추천 순위는 견고합니다."

> 만약 진짜 동일 척도가 필요하면(고도화): ρ를 곱가중으로 쓰거나(방식 X), σ를 직무별 달성률로 재정의하는 방향이 있으나, 임의 가정이 늘어 MVP에선 채택하지 않음(설계 §10 로드맵).
