# 시스템 한계 및 의식적 분리 사항

## 1. 시간표 충돌 ILP 제약 미구현

### 현재 상태
- 홍익대학교 공식 시간표 조회 페이지(`https://cn.hongik.ac.kr/app/timetable/`)를 SOT로 사용해 2026학년도 1학기 학부 시간표를 `data/course_section.csv`에 수용했다.
- 수용 범위는 서울캠퍼스 A200/B010 전공 조회와 비공학 교양(`GE*`), 공학계열 교양/MSC(`ENG_GE*`) 조회를 포함한다.
- 공식 시간표는 학수번호-분반 단위이므로 기존 과목 단위 `data/course.csv`를 무리하게 수정하지 않고, 분반/교원/시간표 정보는 `course_section.csv`에 분리했다.
- 크롤러는 `crawlers/courses/hongik_timetable.py`이며, `hak03.jsp`에서 2026학년도 1학기를 선택한 뒤 hidden `p_yy`, `p_hakgi`를 추출해 `hak03_detail01.jsp`에 POST한다.

### 아직 구현하지 않은 부분
- 추천 ILP에는 아직 분반 선택 변수와 시간표 충돌 제약을 연결하지 않았다.
- `course_section.time_slots_raw`는 공식 표기(`월91011`, `수89,금9`) 그대로 저장하며, 충돌 판정을 위한 정수 슬롯 전처리는 후속 작업이다.

### 영향 분석
**유지되는 ILP 제약 (4개)**
1. 학점 상하한
2. 선수과목
3. 학년 제한
4. 졸업요건 (영역별 min/max + 강제 선택)

**새로 확보된 확장 기반**
- 공식 SOT 기반 2026-1 분반/교원/시간표 데이터
- 과목 단위(`course.csv`)와 분반 단위(`course_section.csv`)의 정규화된 분리
- 향후 `course_id` 매칭을 통해 과목 추천 결과를 실제 개설 분반 후보로 확장 가능

### 데이터 모델 방향
- `course.csv`는 과목 카탈로그/졸업요건/역량 매핑 기준 데이터로 유지
- `course_section.csv`는 학기별 개설 분반 스냅샷으로 유지
- 후속 ILP 확장 시 `course_id`로 조인하고, 분반별 시간 슬롯 전처리 컬럼을 추가해 충돌 제약을 구현

### 발표 시 방어 논리
> "시간표 데이터는 공식 조회 페이지를 SOT로 사용해 학수번호-분반 단위 `course_section.csv`로 수용했다. 다만 이번 범위에서는 추천 ILP에 분반 선택 변수와 시간표 충돌 제약을 연결하지 않았고, 기존 4개 제약(학점, 선수, 학년, 졸업요건)을 유지한다. 데이터는 공식 표기 그대로 보존되어 있어 후속 작업에서 시간 슬롯 전처리와 충돌 제약을 추가할 수 있다."
