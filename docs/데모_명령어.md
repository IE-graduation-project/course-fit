# 데모/실행 명령어 치트시트

ILP 직무역량 과목 추천 — 성적표 적재부터 추천까지 end-to-end 명령어.
모든 명령은 **프로젝트 루트**에서 `.venv/bin/python` 으로 실행한다.

---

## ① 데이터 빌드 — *매핑/과목이 바뀔 때만* (평소엔 생략)

```bash
# 과목이 추가됐을 때만 (LLM 호출, 비쌈). 설명만 바뀌면 캐싱돼 신규분만 생성.
.venv/bin/python mapping/01_generate_descriptions.py

# 점수 재계산 (LLM 없음, 빠름)
.venv/bin/python mapping/03_compute_tfidf.py      --course-only
.venv/bin/python mapping/04_compute_embeddings.py --course-only
.venv/bin/python mapping/05_combine_normalize.py  --course-only   # relevance 가중 포함

# DB 재적재 (⚠️ student/student_course 데이터가 날아감 → 성적표 다시 적재)
.venv/bin/python db/ingest.py --reset
```

> 매핑 수정이 **점수 산출 공식**만 바꾼 거라면(예: relevance 가중) `05`만 재실행하면 된다.
> 01/03/04 산출물(`mapping/intermediate/`)은 그대로 재사용.

## ①-b API 서버 (2026-09-13 추가)

```bash
.venv/bin/uvicorn api.main:app --reload --port 8000
```

| 확인 | 명령 |
|---|---|
| 기동 확인 | `curl -s localhost:8000/health` → `courses: 3304` |
| 참조 데이터 | `curl -s localhost:8000/api/reference` |
| 프론트 연결 | `web/.env.local` 에 `NEXT_PUBLIC_API_BASE=http://localhost:8000` → `npm run dev` |

- 의존성은 `requirements-api.txt` 만 있으면 된다 (fastapi · uvicorn · pulp).
- **로컬 개발에서는 `COURSE_FIT_TTL_HOURS=0`** 을 권한다. 기본 24시간이라 어제 적재한
  성적표가 추천 호출 때 자동 삭제된다(운영에서는 의도된 동작 — 결정 ⑧).
- 환경변수: `COURSE_FIT_DB`(열 경로) · `COURSE_FIT_SEED_DB`(이미지 시드) ·
  `COURSE_FIT_TTL_HOURS` · `COURSE_FIT_CORS_ORIGINS`.

## ② 성적표 적재 (학생마다 1회)

```bash
.venv/bin/python -m transcript --text <파일.txt> --dept <IDE|BIZ> --year <년도>
```

| 인자 | 값 | 비고 |
|------|------|------|
| `--text` | 성적표 txt 경로 | 클래스넷 '성적정보 > 전체성적조회' 복붙. `transcripts/`(gitignore)에 두기 권장 |
| `--dept` | `IDE` 또는 `BIZ` | 유효값 이 둘뿐 (department 테이블) |
| `--year` | **BIZ→2022 이상, IDE→2026 이상** | `admission_year` 는 적용 시작 연도다 — 2025학번 경영은 2022 요건이 적용된다(결정 ⑨) |

- 출력 `input_hash=xxxx` 를 **메모**한다 (추천에서 `--student`로 사용).
- 같은 내용 재실행은 같은 해시로 **덮어쓰기**(idempotent, 중복 안 쌓임).
- `취득학점=None / 평점=None`은 무관 — 추천은 과목 단위로 직접 집계한다.

## ③ 추천 실행

```bash
.venv/bin/python -m recommender --student <hash> --job <직무> [옵션]
```

**필수**

| 인자 | 값 |
|------|------|
| `--student` | ②에서 받은 input_hash |
| `--job` | `DA` 데이터분석가 · `DS` 데이터사이언티스트 · `DE` 데이터엔지니어 · `PM` 프로덕트매니저 · `MKT` 마케팅매니저 · `FIN` 재무분석가 |

**옵션** (안 주면 기본값)

| 인자 | 기본 | 의미 |
|------|------|------|
| `--mode` | `balanced` | 성향 프리셋 = **ε 토글**. `gap`(ε0, 역량우선) / `balanced`(ε0.3) / `graduation`(ε0.6, 졸업·전공우선) |
| `--eps` | (없음) | ε 직접 지정 0~1. **주면 `--mode` 무시** (미세조정용) |
| `--max-credits` | 18 | 학점 상한 U |
| `--min-credits` | 12 | 학점 하한 L |
| `--top-k` | 3 | 대안 시간표 개수 (충돌 없는 동급/차선) |
| `--alpha` | 1.5 | σ 포화곡선 가파름 (낮출수록 변별력↑) |
| `--explain` | off | **추천 근거 카드 출력** (왜 이 시간표인가) |

> **ε에 관해**: `--eps`를 안 줘도 `--mode`의 프리셋 ε이 항상 적용된다(기본 balanced=0.3).
> 따로 ε을 붙일 필요 없고, 커스텀 값이 필요할 때만 `--eps`로 덮어쓴다.

## 자주 쓰는 조합

```bash
# 데모용 — 근거 카드까지
.venv/bin/python -m recommender --student <hash> --job DA --explain

# 졸업·전공 우선 (need-cap으로 영역별 필요량까지만 채움)
.venv/bin/python -m recommender --student <hash> --job DA --mode graduation --explain

# 대안 5개, 21학점 상한
.venv/bin/python -m recommender --student <hash> --job FIN --top-k 5 --max-credits 21

# ε 직접 실험 (mode 무시)
.venv/bin/python -m recommender --student <hash> --job DA --eps 0.45
```

## 보조 확인 쿼리

```bash
# 적재된 학생 목록
sqlite3 db/app.db "SELECT input_hash, dept_id, admission_year FROM student;"

# 성적표 매칭률 (catalog 매칭 / 전체)
sqlite3 db/app.db "SELECT COUNT(*) 전체, SUM(matched) 매칭 FROM student_course WHERE input_hash='<hash>';"

# 직무/졸업요건 정의 범위
sqlite3 db/app.db "SELECT job_id, job_name FROM job;"
sqlite3 db/app.db "SELECT DISTINCT dept_id, admission_year FROM graduation_requirement;"
```

## 파이프라인 한눈에

```
성적표.txt ──②transcript──▶ DB(student/student_course)
                                      │
data/ CSV ──①mapping──▶ ingest ──▶ DB(course/course_competency/course_section/...)
                                      │
                                      ▼
                          ③recommender (ILP 2단계)
                          σ·gap·Score·need 사전계산 → 1순위 CareerFit → 2순위 GradProgress(need-cap)
                                      │
                                      ▼
                          시간표 top-k + --explain 근거 카드
```

설계 상세는 `docs/ILP_추천시스템_설계.md`, 매핑은 `docs/과목과직무_역량_매핑.md` 참조.
