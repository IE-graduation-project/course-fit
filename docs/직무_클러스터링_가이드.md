# 직무 클러스터링 가이드

`data/job_posting.csv`에서 데이터 기반으로 대상 직무를 선정한다.

## 목표

크롤링한 채용공고들의 직무명을 분석하여 본 시스템이 다룰 **직무**를 객관적 근거로 선정한다.

## 입력 / 출력

**입력**: `data/job_posting.csv` (크롤링 완료된 채용공고)
- 컬럼: `job_id`, `source`, `posting_url`, `raw_text`, `crawled_at`
- 현재 `job_id`는 공백

**출력**:
1. `data/job.csv` — 최종 선정된 직무 목록
2. `data/job_posting.csv` — `job_id`를 최종 직무로 갱신
3. `docs/직무_선정_근거.md` — 분석 결과 + 선정 이유

## 작업 절차

### Step 1. 직무명 추출

채용공고 `raw_text`에서 직무명만 추출. 보통 공고 제목에 있음.

```python
import pandas as pd
import re

df = pd.read_csv('data/job_posting.csv')

def extract_job_title(text):
    # 공고 첫 줄 또는 "직무:", "포지션:" 다음 텍스트
    # 사이트마다 패턴 다름. 본인 크롤링 결과 보고 조정.
    lines = text.strip().split('\n')
    return lines[0].strip() if lines else ''

df['job_title_raw'] = df['raw_text'].apply(extract_job_title)
df.to_csv('data/job_posting_with_titles.csv', index=False)
```

**확인 사항**:
- 직무명이 잘 추출되었는지 샘플 20개 눈으로 검증
- 빈 값/노이즈 많으면 추출 로직 수정

### Step 2. 직무명 정규화

같은 직무를 다르게 표기한 것들을 통합.

흔한 변형:
- "데이터 분석가" / "Data Analyst" / "데이터 애널리스트" / "DA" → 하나로
- "프로덕트 매니저" / "PM" / "Product Manager" → 하나로

```python
def normalize_job_title(title):
    title = title.lower().strip()
    # 영어 → 한글
    mapping = {
        'data analyst': '데이터 분석가',
        'data scientist': '데이터 사이언티스트',
        'data engineer': '데이터 엔지니어',
        'product manager': '프로덕트 매니저',
        'marketing manager': '마케팅 매니저',
        'pm': '프로덕트 매니저',
        'da': '데이터 분석가',
        'ds': '데이터 사이언티스트',
        # 본인 데이터 보고 추가
    }
    for k, v in mapping.items():
        if k in title:
            return v
    return title  # 매핑 안 되면 원본 유지

df['job_title_norm'] = df['job_title_raw'].apply(normalize_job_title)
```

**팁**: 정규화 매핑은 데이터 보면서 반복 수정. 처음엔 10~20개로 시작, 데이터 보고 추가.

### Step 4. 직무 선정

다음 기준으로 선정:

**기준 1: 빈도** (필수)
- 상위 N개 안에 들 것
- 너무 적은 직무는 데이터 부족으로 매핑 신뢰도 ↓

**기준 2: 학과 적합도** (필수)
- 산데공·경영 졸업생이 실제 지원할 수 있는 직무
- 백엔드 개발자 같은 직무는 CS 학과가 더 적합 → 제외 또는 신중

**기준 3: 직무 간 차별성** (권장)
- 4개 직무가 너무 비슷하면 추천 차별화 안 됨
- 데이터 분석가 / 데이터 사이언티스트 / 데이터 엔지니어 → 셋 다 데이터 직무. 비슷함. 둘만 골라도 됨
- 데이터 직무 + 경영 직무 섞기 권장

**권장 조합**:
- 데이터 분석가 (DA)
- 데이터 사이언티스트 (DS)
- 프로덕트 매니저 (PM)
- 마케팅 매니저 (MKT)

→ 빈도 + 학과 적합도 + 차별성 3가지 모두 충족 가능성 높음.

### Step 5. job.csv 작성

선정한 3~4개 직무를 `data/job.csv`로 저장.

```csv

DA,데이터 분석가
DS,데이터 사이언티스트
PM,프로덕트 매니저
MKT,마케팅 매니저
```

**job_id 명명 규칙**: 영문 약자 2~4자.

### Step 6. job_posting.csv의 job_id 갱신

원본 `job_posting.csv`의 `job_id`를 최종 직무 ID로 매핑:

```python
def assign_job_id(norm_title):
    if '데이터 분석가' in norm_title or 'data analyst' in norm_title.lower():
        return 'DA'
    if '데이터 사이언티스트' in norm_title or 'data scientist' in norm_title.lower():
        return 'DS'
    if '프로덕트 매니저' in norm_title or '제품 관리' in norm_title:
        return 'PM'
    if '마케팅' in norm_title and ('매니저' in norm_title or 'manager' in norm_title.lower()):
        return 'MKT'
    return None  # 선정된 4개에 안 들면 제외

df['job_id'] = df['job_title_norm'].apply(assign_job_id)

# 선정 직무에 매핑된 공고만 유지
df_filtered = df[df['job_id'].notna()].copy()

# 임시 컬럼 제거
df_filtered = df_filtered[['job_id', 'source', 'posting_url', 'raw_text', 'crawled_at']]

df_filtered.to_csv('data/job_posting.csv', index=False)
print(f"적재 가능 공고: {len(df_filtered)} / 전체: {len(df)}")
```

**검증**:
- 각 직무별 공고 수가 최소 20개 이상인지 확인
- 너무 적으면 추가 크롤링 필요

### Step 7. 선정 근거 문서 작성

```markdown
# 직무 선정 근거

## 분석 데이터
- 크롤링 출처: [사람인/원티드/잡코리아 등]
- 총 공고 수: [N]개
- 크롤링 기간: [YYYY-MM-DD ~ YYYY-MM-DD]

## 직무명 빈도 분포 (상위 10개)
| 직무 | 공고 수 | 비율 |
|------|--------|------|
| 데이터 분석가 | 120 | 30% |
| 데이터 사이언티스트 | 85 | 21% |
| 프로덕트 매니저 | 70 | 18% |
| 마케팅 매니저 | 55 | 14% |
| ... | ... | ... |

## 선정 직무 n개
1. 데이터 분석가 (DA) — 빈도 1위, 두 학과 모두 지원 가능
2. 데이터 사이언티스트 (DS) — 빈도 2위, 산데공 진로 적합
3. 프로덕트 매니저 (PM) — 빈도 3위, 두 학과 모두 지원 가능
4. 마케팅 매니저 (MKT) — 빈도 4위, 경영 진로 적합

## 선정 기준
- 빈도 상위
- 산데공·경영 졸업생 진로 적합도
- 직무 간 역량 차별성 (기술 vs 경영 균형)

## 제외 직무 및 이유
- 데이터 엔지니어: 빈도 5위지만 산데공 데이터 직무 3개 중복으로 차별성 ↓
- 백엔드 개발자: 빈도 6위지만 CS 학과가 더 적합, 본 학과 진로 부적합
```

## 트러블슈팅

**문제: 직무명이 너무 다양하게 표기되어 정규화 어려움**
- 해결: 정규화 매핑 키워드를 늘림. 또는 LLM 호출하여 직무명 정규화 (`openai.chat.completions.create`로 직무명 → 표준명 매핑)

**문제: 선정 직무 중 공고 수가 너무 적은 게 있음 (<20)**
- 해결: 해당 직무로 추가 크롤링. 또는 그 직무 빼고 다른 직무로 교체.

**문제: raw_text에서 직무명이 깔끔하게 추출 안 됨**
- 해결: 크롤링 시 사이트의 "직무명" 필드를 별도 컬럼으로 저장하도록 크롤러 수정 권장. 그러면 추출 불필요.
