# 역량 매핑 구현 설계

과목·직무를 10차원 역량 벡터로 매핑하는 정량 파이프라인. PPT 확정안(정량까지) 기준.

## 0. 범위

- 매핑 결정은 정량 기법(TF-IDF + KoSBERT)으로만 수행
- LLM은 과목 설명 생성(input 풍부화)에만 사용, 매핑 점수 산출에는 미사용
- LLM 교차검증·가중평균·kappa 검증은 본 범위에서 제외 (향후 여유 시 수동 sanity check만)

### 3.3 과목 입력 풍부화 — LLM 설명 생성

스크립트: `01_generate_descriptions.py`

- 입력: course_name, dept_name, area
- 처리: LLM 호출로 학습 내용 설명 생성
- 한계 전제: 홍익대 고유 특성에 정확히 맞지 않을 수 있으나 과목 본질은 유사하다고 가정

```
학부 3~4학년 수준을 가정하며, 해당 학과·과목에서 일반적으로
다루는 표준 내용으로 작성하세요.
```

출력: `data/course_descriptions.csv`

```json
    "onet_code": "15-1252.00",
    "keywords": ["프로그래밍", "코딩", "Python", "파이썬", "Java",

                 "객체지향", "API"]
  }
}
```

10개 역량: PROG, DATA, ML, DB, VIZ, BIZ, FIN, MKT, OR, COMM

## 5. 정량 매핑

과목·직무 동일 로직, 입력 텍스트만 다름.
- 과목 입력: course_descriptions.csv 의 description
- 직무 입력: job_postings_sampled.csv 의 extracted_text (직무별 20개)

### 5.1 TF-IDF (키워드 빈도 기반)

스크립트: `03_compute_tfidf.py`
산데공 기법: 텍스트마이닝, 데이터분석응용

문서 집합 D에 대해:
```
TF-IDF(k, d) = TF(k, d) × log( |D| / DF(k) )
  TF(k, d): 문서 d 내 키워드 k 출현 빈도
  DF(k): 키워드 k를 포함한 문서 수
```

역량 c의 점수:
```
tfidf_score(c, d) = Σ_{k ∈ keywords(c)} TF-IDF(k, d)
```

구현 메모:
- sklearn TfidfVectorizer 사용
- 한국어 토큰화 필요 (공백 기준 또는 형태소 분석기 konlpy). 키워드가 복합어(예: "데이터 분석")라 n-gram 또는 키워드 직접 매칭 방식 고려
- 단순 대안: 키워드별 등장 횟수 × IDF 가중치 직접 계산

출력:
- `intermediate/tfidf_scores_course.csv`
- `intermediate/tfidf_scores_job.csv`
- 형식(wide): course_id/job_id, PROG, DATA, ..., COMM (raw 점수, 미정규화)

### 5.2 KoSBERT 임베딩 유사도 (의미 기반)

스크립트: `04_compute_embeddings.py`
산데공 기법: 기계학습, 데이터분석응용
모델: `jhgan/ko-sbert-nli` (HuggingFace, 무료), sentence-transformers

처리:
```
역량 임베딩:  e_c = KoSBERT(definition_c + " " + keywords_c)
문서 임베딩:  e_d = KoSBERT(description 또는 extracted_text)
유사도:       sim(c, d) = cos(e_c, e_d) = (e_c · e_d) / (||e_c|| ||e_d||)
```

직무 텍스트가 길어 토큰 한도 초과 시: 공고별 임베딩 후 직무 단위 평균.

출력:
- `intermediate/embedding_scores_course.csv`
- `intermediate/embedding_scores_job.csv`
- 형식(wide): 동일, sim 점수(0~1 부근)

### 5.3 결합

스크립트: `05_combine_normalize.py`

각 점수를 결합 전 min-max 정규화로 스케일 통일 후:
```
combined(c, d) = α · tfidf_norm(c, d) + (1 − α) · sim_norm(c, d)
  α = 0.5 (기본, 의미에 더 줄 경우 α 낮춤)
```

α는 상수로 두되 코드 상단에 파라미터로 분리해 조정 가능하게.

## 6. 정규화 (단위 통일)

### 6.1 과목 — 합 = 1
```
weight(c, d) = combined(c, d) / Σ_{c'} combined(c', d)
```
한 과목의 10개 역량 weight 합 = 1.0.

### 6.2 직무 — 0~1 스케일
직무별 독립 min-max:
```
required_level(c, j) = (combined(c, j) − min_c') / (max_c' − min_c')
```
직무 간 합 제약 없음. 각 값 0~1.

## 7. 출력 형식 (long format)

DB 적재 형식에 맞춰 long으로 변환.

`data/course_competency.csv`:
```
course_id,comp_id,weight
140316,PROG,0.17
140316,DATA,0.31
...
```
→ 과목 1개당 10행. 약 194 × 10 = 1,940행.

`data/job_competency.csv`:
```
job_id,comp_id,required_level
DA,PROG,0.65
DA,DATA,0.95
...
```
→ 직무 1개당 10행.

## 8. sanity check (정식 검증 아님)

적재 후 본인 수강 과목 몇 개를 눈으로 확인:
- 데이터사이언스 → DATA·ML 높게 나왔는가
- 회계원리 → FIN 높게 나왔는가
- 마케팅 → MKT 높게 나왔는가

명백히 어긋난 과목만 키워드 사전·α 조정 후 재실행. 코드 부담 없음.
발표 시 "결과 육안 검토" 한 문장 가능.

## 10. 구현 시 결정·주의 사항

- 한국어 토큰화: 복합 키워드("데이터 분석") 매칭을 위해 키워드 직접 매칭 + IDF 가중 방식이 TfidfVectorizer 기본 토큰화보다 안전할 수 있음
- α 기본 0.5, 코드 상단 상수로 분리
- min-max 정규화 시 분모 0 방어 (모든 점수 동일할 때)
- 정규화 후 과목 weight 합 = 1 검증은 ingest.py 검증 2번이 자동 수행
- 단일 역량 쏠림 방지: weight > 0인 역량이 2개 미만이면 flag (선택)
- 중간 산출물은 `mapping/intermediate/`에 두고 gitignore

## 12. 발표 메시지

- 단일 LLM 매핑의 순환 우려를 인지하고, 매핑 결정은 정량 기법으로 수행
- 산데공 학습 기법(TF-IDF=텍스트마이닝, KoSBERT=기계학습) 직접 응용
- 역량 체계는 NCS·O*NET 공식 표준 기반
- LLM은 과목 설명 생성(input)에만 한정 사용

## 13. 한계 및 향후 과제

- 강의계획서 전체 미확보 → 과목 설명을 LLM 생성에 의존 (홍익대 고유 내용 일부 손실)
- 향후: 강의계획서 확보 시 input 대체, LLM 교차검증·Cohen's kappa 검증 추가

  - 산출: `data/course_competency.csv`(~1,920행), `data/job_competency.csv`(60행)

### Phase 3 보정 — 검증 중 발견·수정 (2026-05-27)

초기 결과가 균등분포에 가까워(평균 엔트로피 2.20/최대 2.30) 검증 후 보정. 상세 경위는
`docs/역량매핑_시행착오.md`.

- **키워드 매칭 버그**: ASCII 키워드(`OR`,`AI`)가 영단어 내부(w**or**k, tr**ai**ning)에 거짓 매칭 → 단어 경계 매칭으로 교정(`mapping/03`). 직무 OR 거품(DA OR=1.0) 제거.
- **정규화 변경**: 전역 min-max → **행(문서) 단위 min-max**(`mapping/05`). 극단 문서가 스케일 독점하던 문제 해소.
- **튜닝**: α 0.5→0.7, OR 키워드에서 범용어(`최적화`,`OR`,`제약조건`,`목적함수`) 제거.
