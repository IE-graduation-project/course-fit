# 성적표 파싱 및 학생 DB 적재 설계 (이슈 #16)

> **목적**: 성적표 PDF를 파싱해 학생 정보를 DB에 적재하는 모듈의 설계 명세.
> 추천 파이프라인의 앞단 (1)성적표 파싱 → (2)DB 적재를 담당하며, 뒷단
> (3)시간표 추천(#15)이 이 데이터를 소비한다.
>
> **한 줄 요약**: "학생 성적표 PDF를 넣으면, 학생 메타와 이수 과목을 뽑아
> 추천 엔진이 바로 쓸 수 있는 형태로 DB에 적재한다."

> ⚠️ **갱신 (2026-06-10)**: `student_input` 테이블은 **제거됨.** `student_course`에서
> σ입력(matched∧passed∧¬superseded)을 파생할 수 있어 중복이었다. 적재는 `student`/`student_course`
> 2개 테이블만 쓰고, recommender가 student_course에서 직접 도출한다. 아래 본문의 student_input 관련
> 서술(3-3절 등)은 이 변경 이전 기준이며 무효.

## 1. 파이프라인 위치와 소비자 요구

```
(1) 성적표 파싱  ->  (2) DB 적재  ->  (3) 시간표 추천 (#15)
└──────── 본 이슈(#16) ────────┘        └─ 별도(#15) ─┘
```

추천 엔진(`ILP_추천_설계.md`)이 학생 입력에서 실제로 필요로 하는 값:

| 추천 측 기호 | 의미 | 필요한 원천 데이터 |
|---|---|---|
| `σ_k` | 학생 현재 역량 (기수강 누적) | **이수한 catalog 과목의 course_id 집합** → `course_competency` 조인 |
| `need_g` | 영역 `g` 잔여 졸업학점 = max(0, min_g − 기수강학점_g) | **영역별 기수강 학점** + **학과 + 입학년도**(졸업요건 선택) |
| 후보 필터 | 이미 수강한 과목 후보에서 제외 | 이수한 course_id 집합 |

여기서 두 가지가 현재 스키마에 없어서 본 설계로 채운다.
1. **영역별 기수강 학점**: 성적표엔 catalog(192과목)에 없는 교양/타과/폐지 과목이 섞인다.
   이를 버리면 영역별 학점이 과소집계되어 `need_g`가 부풀려진다 → 성적표 전 과목을 원본 적재.
2. **학과 + 입학년도**: 졸업요건은 `(dept_id, admission_year)`로 분기한다 → 학생 메타 테이블 추가.

## 3. 산출 스키마

기존 `student_input`은 **유지**하고(추천 계약 보존), 두 테이블을 신규 추가한다.

### 3-1. `student` (신규): 성적표 1건 = 학생 1명

```sql
CREATE TABLE IF NOT EXISTS student (
    input_hash      TEXT    PRIMARY KEY,   -- 성적표 내용 해시 (D3)
    student_no      TEXT,                  -- 학번 (성적표에 있으면)
    name            TEXT,                  -- 성명 (있으면)
    dept_id         TEXT,                  -- 매핑된 학과(IDE/BIZ), 매핑 실패 시 NULL
    dept_name_raw   TEXT,                  -- 성적표 원문 학과명
    admission_year  INTEGER,               -- 입학년도
    current_grade   INTEGER,               -- 이번 학기 학년 = 성적 확정된 마지막 정규학기의 다음 학기 (#42)
    total_earned    INTEGER,               -- 총 취득학점 (성적표 합계)
    gpa             REAL,                   -- 전체 평점평균 (성적표 표기)
    source_file     TEXT,                  -- 원본 PDF 파일명
    created_at      TEXT,
    FOREIGN KEY (dept_id) REFERENCES department(dept_id)
);
```

### 3-2. `student_course` (신규): 성적표 전 과목 원본

```sql
CREATE TABLE IF NOT EXISTS student_course (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    input_hash      TEXT    NOT NULL,
    course_id       TEXT,                  -- 학수번호 (없을 수 있음)
    course_name     TEXT    NOT NULL,
    category_raw    TEXT,                  -- 성적표 이수구분 원문 (전필/전선/교양 등)
    area            TEXT,                  -- area enum 매핑값 (실패 시 NULL)
    credit          INTEGER NOT NULL,
    grade_letter    TEXT,                  -- 등급 원문 (A+, B0, P, F, NP 등)
    grade           REAL,                  -- 4.5 환산 (P/N/F 등 비해당 시 NULL)
    is_pn           INTEGER DEFAULT 0,     -- P/N 과목이면 1
    passed          INTEGER DEFAULT 0,     -- 이수(취득) 여부
    term            TEXT,                  -- 수강 학기 (예: 2023-1)
    matched         INTEGER DEFAULT 0,     -- course 카탈로그 매칭 여부
    FOREIGN KEY (input_hash) REFERENCES student(input_hash)
);
CREATE INDEX IF NOT EXISTS idx_sc_hash ON student_course(input_hash);
```

- surrogate PK(`id`) 사용 → 재수강/동일 course_id 중복, course_id NULL을 자연스럽게 수용.
- `passed`: `이수 = (grade >= 1.0) 또는 (grade_letter ∈ {P})`. F/NP/N은 미이수.

### 3-3. `student_input` (기존 유지): 매칭 + 이수 과목

스키마 변경 없음. **이수(passed=1)이면서 catalog에 매칭된 과목만** 적재한다.

```sql
-- (기존) input_hash, course_id, grade REAL NOT NULL CHECK(0..4.5), is_pn
```

- 재수강은 **이수한 최종/최고 성적 1건**만 넣는다(PK가 (input_hash, course_id)이므로).
- P/N 매칭 과목: `is_pn=1`, `grade=0.0`(기존 NOT NULL 제약 보존). **소비자는 `is_pn=1`이면
  grade를 무시**해야 한다(P/N은 GPA 제외가 정의상 당연하므로 안전).
- F/미이수 과목은 넣지 않는다(이수 아님 → σ_k/이미수강/졸업학점 모두 비대상).

## 4. 변환 규칙

### 4-1. 등급 → 4.5 평점

| 등급 | 평점 | 등급 | 평점 |
|---|---|---|---|
| A+ | 4.5 | C+ | 2.5 |
| A0 (A) | 4.0 | C0 (C) | 2.0 |
| B+ | 3.5 | D+ | 1.5 |
| B0 (B) | 3.0 | D0 (D) | 1.0 |
| | | F | 0.0 |

- `P`(Pass) → `is_pn=1`, grade NULL(원본) / 0.0(student_input). `passed=1`.
- `NP`, `N`(Non-pass) → `is_pn=1`, grade 0.0, `passed=0`.
- 표기 변형(`A`=`A0`, `A＋` 전각 등)은 정규화 후 매핑. **실제 표기는 샘플 PDF로 확정.**

### 4-2. 이수구분 → area enum

area enum(`data/README.md`): `교양필수, 특성화교양, SW데이터활용역량, 공통교양,
전공기초영어, 전공필수, 전공선택, 일반선택, MSC, 전공기초, (교양총합=가상)`.

성적표 이수구분 코드(예상, **샘플 PDF로 확정 필요**):

| 성적표 이수구분(예상) | area enum |
|---|---|
| 전공필수 / 전필 | 전공필수 |
| 전공선택 / 전선 | 전공선택 |
| 전공기초 / 전기 | 전공기초 (경영) |
| 교양필수 / 교필 | 교양필수 |
| 공통교양 / 교양선택 | 공통교양 |
| 특성화교양 | 특성화교양 |
| 일반선택 / 일선 | 일반선택 |
| MSC | MSC |
| (SW/데이터 활용) | SW데이터활용역량 |
| 전공기초영어 | 전공기초영어 |

- 매핑 실패 시 `student_course.area = NULL`로 두고 로그(집계에서 제외, 경고로 노출).
- **이 표는 가설**이다. 홍익대 성적표의 실제 이수구분 명칭은 샘플 PDF 확인 후 확정한다.

### 4-3. 학과명 → dept_id

| 성적표 학과명(예상) | dept_id |
|---|---|
| 산업데이터공학과 (공백/구분점 변형 포함) | IDE |
| 경영학과 / 경영학전공 | BIZ |
| 그 외 | NULL (경고) |

### 4-4. input_hash 산출 (D3)

정규화한 성적표 핵심 내용으로 결정적 해시를 만든다.

```
key = (학번 또는 성명) + sorted([(course_id, term, grade_letter, credit) ...])
input_hash = sha256(key의 정규화 문자열)[:16]
```

- 같은 성적표 재업로드 → 같은 hash → 적재 전 해당 hash의 기존 row 삭제 후 재적재(idempotent).
- 학기 추가/성적 정정으로 내용이 바뀌면 새 hash가 되므로 최신본이 별도로 쌓인다.

### 추천 모듈(#15)과의 인터페이스 계약

소비자는 둘 중 편한 쪽을 쓴다.

1. **DB 경유(권장)**: `student`, `student_course`, `student_input` 3테이블을 읽는다.
   - `σ_k`: `student_input`(매칭, 이수 과목) ⋈ `course_competency`
   - `need_g`: `student_course`(passed=1)에서 area별 credit 합, `student`의 dept_id+admission_year로 졸업요건 선택
   - 이미수강 필터: `student_input.course_id` 집합
2. **함수 경유**: `parse_transcript(pdf_path) -> TranscriptResult` 구조화 객체 반환.

```python
@dataclass
class StudentMeta:
    student_no: str | None
    name: str | None
    dept_id: str | None
    dept_name_raw: str | None
    admission_year: int | None
    current_grade: int | None
    total_earned: int | None
    gpa: float | None

@dataclass
class TakenCourse:
    course_id: str | None
    course_name: str
    category_raw: str | None
    area: str | None
    credit: int
    grade_letter: str | None
    grade: float | None
    is_pn: bool
    passed: bool
    superseded: bool   # 재수강으로 대체된 이전 시도 (집계 제외, 이력 보존)
    term: str | None
    matched: bool

@dataclass
class TranscriptResult:
    input_hash: str
    meta: StudentMeta
    courses: list[TakenCourse]
```

## 6. 입력 트랙 2개

| 트랙 | 입력 | 상태 | 파서 |
|---|---|---|---|
| 1. PDF | 성적표 PDF | 미정 (양식 미확보) | `parse.py` (레이아웃 의존부 미구현) |
| 2. 복붙 | 클래스넷 전체성적조회 Ctrl+A/C/V 텍스트 | **구현 완료** | `parse_text.py` |

### 6-1. 전체성적조회 복붙 포맷 (트랙 2, 실제 샘플 분석)

- 학기 헤더: `2022학년도 1학년 1학기` (학년은 0/N 가능, 학기는 1/2학기/하계계절학기/동계계절학기)
- 컬럼(탭 구분): `학수번호, 과목명, 영문과목명, 학점, 성적, 재수강`
- 성적: `A+ ~ D0`, `P`, `F`, 또는 **공란**
- 마지막 `전체성적` 블록: 총 취득학점, 총 증명평점, 백점환산
- footer 규칙 반영:
  - **일반과목 F = 공란**, P/N과목 F = `F` 표기 -> 둘 다 미이수(passed=0)
  - **재수강 표시 행 = 대체된 이전 시도** (성적증명서 미포함) -> `superseded=1`, 집계/`student_input` 제외, 이력은 `student_course`에 보존
  - 이수 = `D0(1.0)` 이상 또는 `P`
  - 전체성적조회엔 **성적 확정 학기만** 노출 -> 공란을 F로 처리해도 진행중 과목 오인 없음

**이 포맷의 한계 2가지:**
1. **이수구분 컬럼이 없음** -> 미매칭 과목의 영역(area)은 catalog 매칭에 의존 (아래 6-2).
2. **학번/학과/입학년도 없음** -> 학과/입학년도는 **학생이 직접 입력**(인자로 받음). 입학년도는 최초 1학년 학년도로 추론 가능(보조).

### 6-2. area 소스: catalog 매칭 + 일반선택 fallback

area는 두 단계로 정한다.
1. **catalog 매칭 과목**: `course.area`를 권위값으로 부여 (이수구분보다 세분).
2. **미매칭 과목**: 파서 제공 area(PDF 트랙의 이수구분)가 있으면 그 값, 없으면 **일반선택 fallback**.
   `load.FALLBACK_AREA = "일반선택"`. 졸업규칙상 어느 영역 요건에도 안 걸리는 과목은 일반선택(catch-all)이므로,
   catalog가 불완전해도 어떤 성적표든 영역 결측 없이 적재된다(일반화 장치).

**catalog 보강(이슈 #18) 결과**: 전체 학과 다년도 크롤로 catalog를 192 -> 3,304과목으로 확장.
실샘플(BIZ 2022, 90학점) 기준 매칭 13미매칭 -> 3미매칭(3학점). 영역별 기수강학점:
공통교양 26, 전공필수 15, 전공기초 15, 전공선택 15, 일반선택 8, 교양필수 6, 전공기초영어 2.

> 잔여 미매칭(정규 시간표 밖 영어과목 등)과 폐지 과목은 일반선택 fallback이 처리한다.
> 파서/적재 로직은 catalog 품질과 무관하게 동작하며, catalog(#18)가 보강될수록 매칭이 정확해진다.

**주의(추천 측 협의)**: 시간표 이수구분은 개설 학부 관점이라, catalog는 전공 과목을 소유 학부(BIZ/IDE)
관점의 area로 저장한다(타과 전공은 #18에서 일반선택으로 환산). 학생 본인 학부 기준 환산은 추천(need_g)이 담당.

### 6-3. PDF 트랙(트랙 1) 보수적 골격

실제 PDF 양식이 아직 없으므로 본 적 없는 표 레이아웃을 추측하지 않는다(보수적).
`parse.parse_transcript_pdf`는 트랙 2와 동일한 시그니처로:
1. `extract_pdf_text`(pdfplumber)로 PDF 전체 텍스트를 뽑고,
2. 검증된 텍스트 파서(`parse_transcript_text`)에 위임한다(성적표 텍스트가 복붙과 유사하다는 보수적 가정),
3. 과목을 0건 뽑으면 `TranscriptParseError`로 명확히 실패한다(조용한 빈 결과 금지).

**샘플 확보 후 보강(여기만 손대면 됨):**
- PDF가 표 형태면 `extract_pdf_rows`를 pdfplumber `extract_tables` 기반으로 구현해 `_row_to_course`(dict)로 변환.
  성적증명서에 이수구분 컬럼이 있으면 `category_raw`로 받아 area를 정밀화(catalog 매칭보다 우선 가능).
- 학번/성명/학과/입학년도/총취득/평점 메타 추출 위치 확정. PDF 종류(텍스트 vs 스캔, 후자면 OCR) 확인.
